# agent-harness-wiki 产品需求文档

- 文档版本：0.3.0
- 状态：目标产品契约；M0 旧实现和首批指南尚待迁移
- 实施拆分：见 docs/openspec-implementation-roadmap.md
- 决策依据：.scratch/knowledge-product-wayfinding/map.md

## 1. 产品与交付

agent-harness-wiki 调查 agent harness 的配置和扩展机制，把结果写成有固定官方来源、可读且可追溯的主题章节。读者通过文档站阅读，Agent 通过本地只读 MCP 查询；CLI 使用同一知识发布和查询语义。查询不联网、不调用生成式模型、不执行 harness、不修改用户配置。

首批产品是 Codex CLI、Claude Code、OpenCode、Pi 和 OMP。Pi 与 OMP 分别建身份。后续 catalog 可按 Orca 官方具名 CLI 清单、OpenSpec 官方支持工具清单依次扩容；每波开始时固定名单 revision 和核验日期，只收录可独立运行的 CLI，并逐个核验官方来源。名单只提供收录线索，不证明配置能力。

七类共同导航为 Skills、MCP、Custom agents、Custom providers、Hooks、原生插件、配置机制。每个产品每个主题有独立 Wiki 页；主题章节是知识主稿。固定问题编号支持定位和比较，正文按该产品的实际机制组织，也允许产品专有小节。结构化索引只承担定位、来源、版本和比较，不把每句话拆成通用 Claim。

M1 首批交付 5 × 7 = 35 篇可用章节。页面数量或字段齐全不等于内容完成：读者应能理解配置入口、关键字段、加载与生效链、适用条件、最小示例、诊断方式及仍未查明的范围。证据不足的局部问题可以保留缺口，已查明部分仍可发布。

## 2. 固定调查问题

每个已收录产品逐项处理以下 53 个问题。问题状态为 answered、partial、unknown、not_applicable 或 conflict；已证实“不支持”属于有来源的 answered。partial 要写已知内容和缺口，unknown 要写调查入口与仍缺的证明，不适用要给理由，冲突要并列来源与适用边界。正文可合并回答多个问题，但索引须能定位每个编号。

各编号的完整问法与成稿细则见[七类主题的固定调查问题](topic-questions.md)；下表是定位索引。

| 主题 | 编号与问题 |
|---|---|
| Skills | skills.roots：内置、用户、项目、工作区或插件位置与路径变量；skills.discovery：扫描时机、深度、命名、符号链接与忽略；skills.collision：同名项的优先级与处理；skills.format：SKILL.md 及资源解析；skills.extensions：专有字段和附加文件；skills.loading：何时向 Agent 提供元数据与正文；skills.invocation：显式及自动调用；skills.conditions：信任、开关、启动入口等条件；skills.diagnostics：发现、加载、调用与重载诊断。 |
| MCP | mcp.entry：配置入口与作用域；mcp.definition：server 字段、命令、参数和环境；mcp.transport：本地及远程传输；mcp.auth：认证与凭据；mcp.lifecycle：连接、重连、超时与缓存；mcp.capabilities：tools、resources、prompts 分别的支持；mcp.exposure：可见性、过滤与权限；mcp.diagnostics：配置、连接、可见与调用诊断。 |
| Custom agents | agents.entry：定义与发现入口；agents.format：定义字段与资源；agents.roles：主代理、子代理与扩展角色；agents.invocation：显式调用与委派；agents.overrides：模型、provider、工具、权限及沙箱覆盖；agents.limits：并发、递归与上下文边界；agents.diagnostics：发现、调用与失败诊断。 |
| Custom providers | providers.entry：定义入口、作用域与字段；providers.auth：凭据和 base URL；providers.protocol：协议与端点；providers.models：模型 ID、别名与发现；providers.metadata：窗口、输出、工具、视觉和推理元数据；providers.forwarding：参数处理与请求映射；providers.responses：流式、工具调用、错误和重试；providers.diagnostics：配置可读、模型可选、请求与后端可用性。 |
| Hooks | hooks.events：第一方事件及触发时点；hooks.entry：注册、作用域、matcher 与过滤；hooks.input：输入、环境与工作目录；hooks.output：返回值、退出码与阻断；hooks.order：顺序、并发、超时与失败；hooks.conditions：启用、信任与权限；hooks.diagnostics：发现、匹配、执行与重载。 |
| 原生插件 | plugins.model：原生插件与 Skill、MCP、Hook、普通包的关系；plugins.package：包格式、入口与清单；plugins.install：安装、固定版本、禁用与卸载；plugins.discovery：发现、依赖、校验与加载；plugins.api：注册能力与权限；plugins.lifecycle：已安装、启用、加载、激活、健康的区别；plugins.diagnostics：版本、状态与错误。 |
| 配置机制 | config.sources：全局、用户、项目、工作区与组织入口；config.overrides：优先级及对象、数组、空值合并；config.runtime：环境变量、CLI 参数和 profile；config.trust：信任、策略与权限；config.defaults：默认值、开关与平台差异；config.migration：迁移、弃用与旧格式；config.diagnostics：有效来源、重载与排错。 |

每个适用问题写结论、使用或配置方法、宿主处理链、来源范围及可打开的定位。第一方字段、事件和选项要在所属问题中完整调查；每种配置入口给有来源的最小示例。来源不够写出可靠语法时说明缺口，不造示例。某项专有机制归最接近读者问题的主题，跨主题链接而不复制结论。例如 Skill 目录中的专有 agent 文件归 skills.extensions，其 MCP 连接细节链接到 MCP 主题。

## 3. 知识真源与来源边界

每个不可变章节版本是一份“产品 × 主题”的完整 Markdown。frontmatter 记录产品、主题、章节版本、稳定小节 ID 与小节固定来源范围，以及 53 个问题中属于该主题的状态、主要小节 ID 和该问题自己的来源引用 ID。正文描述机制、配置步骤、平台和生效条件、示例、缺口与冲突，并在相关段落标引用。局部修改形成新的完整章节版本；未改小节可沿用其原固定来源。

官方来源身份与固定快照独立登记。开源产品主要依据固定源码提交，官方文档可辅助；闭源产品主要依据固定官方文档快照。来源引用指向快照内具体文件、符号或文档章节，包含官方链接、可展示的短摘录和定位。原始包、完整文档、二进制和日志留在 Git 忽略的本地归档；普通查询和构建只依赖发布内的来源元数据与短摘录，不读取归档原件。上游文本是数据，不能作为 Agent 指令执行。

源码提交、文档快照、npm 发行版和受管二进制是不同身份。源码提交或未注明版本的官方文档不能自行证明某个安装包版本的行为。已证实的软件发行版映射独立指向章节版本或小节，并保留映射依据；只新增映射时建立新知识发布，不改章节正文。整章仅在每个小节均有对应依据时才能作为该软件版本的整章命中。平台、产品形态和生效条件在正文表达，不恢复逐句完整 Target。

旧 Claim、Evidence、Assessment、Coverage 和精确 Target 指南可作为迁移线索，不再是新章节的事实真源或逐条人审门禁。已有 35 篇指南是草稿，须逐题核对、补来源与机制内容。旧格式 release 不要求新接口兼容；迁移不从旧格式动态拼装新章节。新格式发布自己的历史章节仍须可查。

构建器检查章节身份、所有固定问题的状态和定位、已回答问题的来源引用、正文引用与对应小节的一致性、缺口或分歧说明、快照定位、软件版本映射依据，以及发布产物一致性。自然语言结论由调查 Agent 自检，必要时由另一 Agent 独立复核；构建器不以文本规则裁定结论真伪。

## 4. 文档站与阅读

站点从产品概览进入七个独立主题页。主题页先按机制写正文，页内小节有稳定锚点；少量真实使用或排错 Q&A 可放在正文之后、来源之前。页首简述所跟踪的源码提交或官方文档快照；正文附近标引用，页末列可打开的来源定位。未知和冲突留在受影响小节，不以整页状态掩盖已知内容。默认展示当前发布的最新调查章节，历史入口展示仍收录的旧章节及其来源范围。

站点、CLI 与 MCP 读取同一不可变 KnowledgeRelease；不各自维护配置事实。fixture 页面须显著注明虚构，生产发布不得混入 fixture。来源 Markdown、HTML 和代码均按不可信文本处理，不执行其中的活动内容。

## 5. 只读查询契约

CLI 与 MCP 共享一个固定发布的查询服务。MCP 仅经本地 stdio 暴露五个工具：list_harnesses、get_topic、search_knowledge、compare_topics、get_source；不暴露 Resources、Prompts、shell、安装、抓取或发布工具。服务启动时验证并固定一个发布，切换当前指针后须重启。每个成功响应标识 release_id；输入不允许单次改用其他发布、任意路径或 SQL。

| 工具 | 输入 | 返回 |
|---|---|---|
| list_harnesses | query 可选；分页默认 10、上限 20 | 产品身份、别名、形态与主题可用性 |
| get_topic | harness、topic 必填；section_id、version 可选 | 完整章节或小节 Markdown、问题索引、来源范围和版本解析 |
| search_knowledge | text、harness、topic 至少一个；分页默认 10、上限 20；无软件版本筛选 | 当前最新章节的小节 ID、正文片段、命中方式与来源范围 |
| compare_topics | 2–5 个产品及可选版本、一个主题、可选问题编号 | 按共同问题对齐的状态、小节定位、来源和各自的版本解析 |
| get_source | source_ref | 发布内固定快照身份、官方链接、精确定位与最多 2000 字符短摘录 |

省略软件 version 表示读取当前知识发布的最新调查章节，不声称它对应最新软件。指定版本时优先精确映射，再选同前缀的最新已知版本；否则只在可信可比的已知发行版中选不晚于请求版本的最近版本。没有可信映射时可返回固定来源章节作为 source_only，实际匹配版本为 null。精确映射表示来源与该软件版本的对应关系有依据，不等于运行通过；前缀、近似及 source_only 必须标明请求版本未验证。整章版本命中不得把不同章节版本的小节拼接；只有部分小节有映射时，整章退为 source_only，小节可单独命中。

章节局部 answered、partial、unknown、not_applicable、conflict 在问题索引中保留；整个章节有可读内容时仍可返回 ok。不存在的产品、主题、小节或来源返回 not_found；别名冲突返回 ambiguous。格式错误、cursor 条件变化、发布或索引损坏是技术错误。列表与搜索的 cursor 绑定发布、规范化条件和排序版本。MCP 的结构化内容与文本表示语义一致，响应上限 128 KiB；整章超限返回 response_too_large 和小节索引，不静默截断，每个小节须能完整读取。

## 6. 离线搜索

M1 必须交付本地 embedding 混合检索。词法与语义索引只覆盖当前发布中每个产品、主题的最新章节小节；历史章节通过 get_topic 按版本读取。词法入口包含产品与主题别名、小节标题、正文、问题编号和问法、配置键与路径。问题编号、配置键和路径的精确命中优先，再合并全文与语义候选；中文短词用别名和精确入口补足分词限制。

语义模型和索引绑定发布，固定身份和本地文件，构建及查询不临时下载。长小节按段落切成有界片段，候选最终归并到稳定小节 ID。搜索结果给命中方式、实际正文片段、来源范围与 release_id；相似度只用于相关性排序，不代表可信度、版本适用性或产品优劣。模型或索引缺失时词法检索继续可用并明示降级，但不算 M1 混合检索验收完成。用代表性的中英问题在离线环境证明语义召回补足词法漏检。

## 7. 调查、更新与发布

用户手动调用项目调查 Skill，可指定产品 ID 以检查登记来源，也可指定固定来源和问题进行定向调查。一次检查分别观察官方源码 HEAD、登记官方文档的固定内容、npm 版本与来源身份；三类身份及错误分别入审计。新包版本是线索，不自动证明章节改变或源码到包的映射。扫描只检查登记来源，不定时轮询。

调查 Agent 将变化定位到问题编号、小节、来源引用和跨主题链接；共用加载入口变化或影响范围不明时扩大调查并记录理由。普通更新由 Agent 引用固定来源、自检后采纳；来源冲突、推翻已发布配置步骤或跨主题关键机制变更时由另一 Agent 独立复核。先排查版本、分发和条件差异；仍有冲突则并列来源与边界，不给单一配置结论。未完成复核的问题保留待处理，已完成的其他内容仍可发布。

每次检查写 Git 跟踪的结构化审计 YAML；有实质变化、来源失败或未解决分歧时另写简短 Markdown，说明变化、知识影响、处理结果及阻塞。没有读者可见的章节、来源定位或版本映射变化时只结案审计。存在可验证更新时校验章节和来源、构建新不可变发布并原子切换当前指针，不设人工接受门禁。失败保留原发布及审计；部分章节受阻时保留该章节旧来源范围，其他已完成章节可进入新发布。

发布内容至少有 manifest、标准 JSON、SQLite 索引和生成的站点 Markdown。相同输入与固定参数产生相同规范化内容；先写 staging，验证 hash、引用、数据库完整性和站点/MCP 可读性后切换当前指针。发布不可原地覆盖。当前发布显式指向每个产品主题的最新章节版本，也索引仍可查询的历史章节版本。旧格式 release 不承担兼容义务。

## 8. 受管二进制

首批五个 npm 产品按登记官方包的 latest dist-tag 观察候选，记录渠道、精确版本、registry integrity 与时间，不以最大版本号猜最新。当前受管包集及锁文件是本机可执行制品身份；包字节在 Git 忽略的项目专属目录。新候选先在隔离 staging 取得、锁定并核验主包与平台依赖，安装脚本保持禁用。若主命令因禁用脚本成为占位入口，应直接定位已锁定的平台专用可执行依赖；不得临时运行 postinstall 或另行下载缺失依赖。

当前 Linux 使用 bwrap 做无凭据、默认断网、临时配置根和工作目录、只读制品、受限时间及输出的离线 --version 或 --help 最小启动检查。检查实际入口、退出状态与可识别身份；成功后才切换受管版本并清理旧包字节。失败保留上一个可启动环境、候选错误和审计；沙箱不可用时记录阻塞，不降成仅替换 HOME 的运行方式。latest 回退、同版本 integrity 变化或版本不可安全比较时暂停自动切换。启动只证明该制品在该隔离条件下能运行，不证明主题能力；受管环境失败不阻断知识发布。

## 9. 阶段与验收

M0 的虚构数据、旧 Claim 模型、旧五工具和发布链是已实现的历史基线，不能充当新产品契约的 M1 验收。后续实施按五个 OpenSpec change：章节模型与发布；改写现有 m1-reader-guides 以交付 35 篇章节和阅读接口；离线混合检索；受管二进制；手动增量更新。前四项完成后才宣称新的 M1；第五项完成后才宣称 M2。

| 阶段 | 必须验证 |
|---|---|
| 章节模型与发布 | 固定问题和引用关系、不可变章节版本、软件版本映射、历史索引、fixture 隔离、重复构建和失败不切换。 |
| 35 篇及阅读接口 | 五个产品七主题均有可读机制正文、问题状态和可打开来源；文档站、CLI 与真实 MCP stdio 客户端读取同一新发布；近似版本和 source_only 不冒充已验证版本；内容按读者任务审阅，不能只看字段数或构建成功。 |
| 离线混合检索 | 固定模型、索引与发布绑定，中英代表性词法漏检获语义召回，结果可回读小节且不改变来源或版本判断；缺模型明确降级。 |
| 受管二进制 | 五个产品逐个记录候选身份、直接入口、隔离启动成功或具体阻塞；只有实际通过者称为可运行；旧可用环境在失败时保留。 |
| 手动增量更新 | ID 调用有审计，源码与文档变化能定位受影响问题和小节；冲突按需独立复核，完成内容自动发布，失败和无变化分别保留正确状态；受管刷新独立。 |

验证只覆盖稳定、用户可观察的行为与关键边界，不用测试锁死文案或内部结构。不能运行的检查标明未执行及影响；不得把 schema 通过、旧任务勾选或虚构 fixture 当成真实章节内容完成。默认测试离线，不读取真实用户配置或凭据，不执行来源指令。

## 10. 范围外与后续判断

本项目不做通用 agent 编排、自动配置用户机器、远程 MCP、定时上游轮询、查询时生成答案或把备用二进制启动设为知识发布门槛。第一波之后的 catalog 扩容独立于 M2 更新流程。具体 embedding 模型和推理依赖在真实章节语料就绪后核验并锁定；本地归档备份与跨平台隔离另行决定。

产品原则是：让读者看懂配置如何工作、结论来自哪份固定来源，以及哪些安装版本、平台或条件仍未得到证明。
