# 七类主题的调查与成稿契约

本文件是[“细化七类主题的调查问题与章节内容”](issues/04-topic-contract.md)的规划资产。面向每个已收录 Harness，以固定的官方源码提交或官方文档快照调查下列问题。七类主题提供共同导航；表内编号是问题身份，不规定最终页面必须使用相同的标题或段落顺序。产品专有机制可以增加问题，但不能覆盖或略去已有问题。

## 一个问题怎样形成可用答案

每个适用问题写明：结论；用户需要怎样配置或使用；宿主怎样发现、解析、选择或执行；适用的来源提交或文档快照；能打开的文件、符号或文档章节定位。机制解释写成读者能理解的处理链，不转写调用栈。页面可按产品实际机制重排小节，但每个问题编号必须能定位到答案。

第一方配置字段、事件和选项在其所属问题中列全，并说明用途和影响生效的条件。大量同类项可用表格；第三方扩展另标实现者与安装前提。配置入口各给一个最小示例，说明示例依据哪个来源；来源不足以写出可靠语法时写明缺少的内容。示例无需事先运行二进制。

找不到某项机制时，记录检查过的直接入口和剩余缺口。若固定来源明确说明不提供该机制，可写出相应结论及来源。来源互相冲突时，同时展示各自说法和定位，让读者看到适用边界。其他已查明的问题仍正常发布。来源更新后，只复查可能受影响的问题与交叉引用。

## Skills

<!-- prettier-ignore -->
| 编号 | 必答问题 |
|---|---|
| `skills.roots` | 从哪些内置、用户、项目、工作区或插件位置寻找 Skill？路径如何随 home、当前目录、仓库根目录和环境变量变化？ |
| `skills.discovery` | 何时扫描？目录深度、文件名、嵌套目录、符号链接、忽略规则与发现范围是什么？ |
| `skills.collision` | 同名 Skill 怎样去重、覆盖、合并或保留命名空间？搜索顺序与优先级如何影响结果？ |
| `skills.format` | `SKILL.md` 的 frontmatter、正文和资源目录怎样解析？哪些字段必须、可选、受限制或被忽略？ |
| `skills.extensions` | 宿主识别哪些专有字段、附加文件和配置项？逐项说明文件位置、字段、默认值、用途与解析规则。 |
| `skills.loading` | 名称、描述和正文分别何时进入 Agent 上下文？调用后怎样读取正文或资源？ |
| `skills.invocation` | 用户、模型或工具怎样显式或自动调用 Skill？禁用、依赖或策略怎样影响可用性？ |
| `skills.conditions` | 信任、启动入口、功能开关、插件状态或其他条件怎样改变上述行为？ |
| `skills.diagnostics` | 怎样查看发现、选择、加载及调用结果？改动文件后如何重载或重新启动？ |

## 跨主题与专有机制

某项机制的配置和作用写在最接近读者问题的主题中；通用加载顺序和合并规则写在“配置机制”，其他章节链接过去。比如固定 Codex 源码中 Skill 目录下的 `agents/openai.yaml` 属于 `skills.extensions`：调查它的文件位置、字段、解析及对调用策略的作用；其中 MCP 依赖的连接细节链接到 MCP 主题。这里仅规定归类方式，不据此断言某个发行包已实现相同行为。
