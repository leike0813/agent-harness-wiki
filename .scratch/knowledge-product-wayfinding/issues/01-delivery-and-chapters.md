# 确定知识库的交付物与主题主稿

Type: grilling
Status: resolved
Parent: [重新确定知识库交付与维护契约](../map.md)

## Question

知识库以什么形式交付，章节与结构化记录何者为主，如何表达主题与来源的适用范围？

## Resolution

- 文档站提供各 agent harness 的能力配置细节；MCP 提供 Agent 友好的同一批知识。两者是面向使用者的交付物。
- 保留 Skills、MCP、Custom agents、Custom providers、Hooks、原生插件、配置机制七类共同导航；每类要有固定调查问题，同时允许产品特有小节。
- 主题章节是调查成果的主稿。章节说明配置方法、加载机制、例子、适用范围和来源；结构化信息只保留检索、定位、比较与来源追踪需要的部分，不要求把每句话拆为 Claim。
- 每个适用主题的固定问题均须调查，回答已知结论、不适用原因或具体缺口。可用部分不因其他问题未查完而停用。
- 开源项目的结论绑定所查源码提交，闭源项目的结论绑定官方文档快照。对于无法证明与该提交对应的安装版本，可展示所跟踪的上游知识，但明确其来源边界，不声称已验证该安装版本。
- MCP 以取得完整主题说明为主要入口，并支持搜索、来源查看及按小节读取；每个小节有稳定 ID 和来源引用。

这些选择来自本轮对话中用户对 Q1、Q2、Q4、Q5、Q6、Q10、Q11 的采纳。
