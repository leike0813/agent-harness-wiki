# 确定结构化知识的最小模型

Type: grilling
Status: resolved
Assignee: codex
Parent: [重新确定知识库交付与维护契约](../map.md)
Blocked by: [细化七类主题的调查问题与章节内容](04-topic-contract.md), [确定 MCP 工具参数与返回契约](06-mcp-contract.md)

## Question

以主题章节为主稿后，哪些字段需要机器可读，哪些应留在正文？现有 Claim、Evidence、Assessment、Coverage、Target 中哪些有实际查询或维护用途，应简化、合并或保留？怎样确保站点与 MCP 读取同一知识，而不重新建立逐句人审门禁？

## Context

[“确定 MCP 工具参数与返回契约”](06-mcp-contract.md)要求当前知识发布的只读索引可查询仍保留的历史章节，供版本前缀、精确版本及向前最近匹配使用。此议题决定这些章节、软件版本映射、来源范围与默认最新章节如何存储和维护。

## Discussion

- 用户确认：新知识真源以主题章节取代逐条 Claim 和 Assessment；现有事实迁入带固定来源定位的章节。调查 Agent 自检及必要的独立复核写入更新审计，不再逐条人工接受。
- 用户确认：章节内容更新时保存不可变的完整“产品 × 主题”章节版本；局部修改也产生新的完整版本，未修改小节沿用原来源引用。当前知识发布索引仍可查询的历史章节。
- 用户确认：结构化保存章节或小节的固定来源，以及有证据的软件发行版对应关系；平台和生效条件在正文说明，不恢复逐句完整 Target。
- 用户确认：固定调查问题编号记录 `answered / partial / unknown / not_applicable / conflict` 状态和主要小节定位；已证实“不支持”属于 `answered`，`partial` 在正文保留已知内容及缺口。
- 用户确认：固定来源快照独立登记；章节正文通过引用 ID 指向具体文件、符号或文档位置及短摘录，问题索引定位正文小节。`get_source` 读取发布中的同一引用，不再维护 Claim 与 Evidence 的逐条关联。
- 用户确认：软件发行版映射与不可变章节版本分开保存，映射指向有依据的章节版本或小节。仅新增映射时建立新知识发布，继续引用原章节版本；整章只有各小节均有对应依据时才能作为该软件版本的整章命中。
- 用户确认：发布校验覆盖必答问题的状态与定位、已回答内容的可解析来源引用、局部缺口或分歧说明，以及软件版本映射依据；Agent 自检和按需独立复核留在审计中，构建器不重新裁定正文结论。
- 用户确认：问题索引还须记录该问题自己的来源引用 ID；正文在相应段落标注引用。发布校验核对问题引用出现在其定位的小节，避免同节多个问题互相继承无关来源。
- 用户确认：每个不可变章节版本以一份 Markdown 维护；frontmatter 存章节身份、小节来源范围，以及问题状态、小节 ID、引用 ID；正文写机制、条件、示例和引用。固定来源及引用记录、软件版本映射分别用结构化文件维护；发布清单显式指定当前章节版本并索引保留的历史版本。站点与 MCP 由同一发布数据构建。

## Resolution comment

知识真源以不可变的“产品 × 主题”完整章节版本为单位。每个版本是一份 Markdown，frontmatter 记录章节身份、稳定小节及其固定来源范围，并按必答问题编号记录 `answered`、`partial`、`unknown`、`not_applicable` 或 `conflict`、主要小节 ID、该问题的来源引用 ID。正文按机制叙述配置、处理链、适用平台与条件、例子、未知范围和冲突，并在相关段落标引用。已证实“不支持”属于有来源的 `answered`；`partial` 保留已知内容并点明缺口。旧的通用 Claim、Assessment、Coverage 与逐句 Target 不再作为新章节的真源或发布门禁。

官方来源及固定源码／文档快照独立登记。引用记录包含快照身份、官方链接、可打开的文件／符号或文档定位、可展示短摘录；`get_source` 读取发布内同一记录。问题级引用避免同节其他问题继承无关依据。章节发生局部修改时形成新的完整版本，未改小节仍指向原固定来源。

有证据的软件发行版映射单独指向章节版本或小节。只新增映射时，建立新知识发布并沿用原章节版本；只有每个小节都具备对应依据，整章才能作为该软件版本的命中。发布清单显式指定当前调查章节，并索引仍可查询的历史章节，不靠源码提交日期或文档采集时间推断软件版本。平台和生效条件留在正文，不恢复逐句完整 Target。

构建器检查必答问题状态与小节定位、已回答内容的引用存在且能在相应小节找到、缺口和分歧说明、来源快照与定位、软件版本映射的依据，以及发布产物一致性。Agent 自检及按需第二 Agent 复核记录在更新审计中；构建器不裁定自然语言结论。站点和 MCP 都从同一知识发布构建。现有数据与 PRD 的迁移归[“确定现有实现迁移与 OpenSpec 修订边界”](09-migration-handoff.md)安排。
