# 确定搜索与本地 embedding 的定位

Type: grilling
Status: resolved
Assignee: codex
Parent: [重新确定知识库交付与维护契约](../map.md)
Blocked by: [确定 MCP 工具参数与返回契约](06-mcp-contract.md)

## Question

当检索对象改为主题章节与小节后，关键词、别名、全文索引是否足以支持 Agent 查找？当前 M1 的本地 embedding 要继续作为交付要求、改为可选优化，还是取消？若保留，应索引哪些已发布文本，并如何展示相关性与来源边界？

## Discussion

- 用户决定保留本地 embedding 为 M1 必交付项；新章节搜索仍须提供离线混合检索，而非只在词法漏检时选择性实现。
- 用户确认：词法检索只索引当前知识发布的最新主题章节小节，纳入小节标题、正文、固定调查问题编号与问法、配置键和路径；产品与主题别名用于归一化。历史章节由 `get_topic` 按版本读取，避免搜索结果重复占满。
- 现有实现仍用 Claim FTS 和指南正文字符串包含搜索；旧 PRD 把 embedding 建在已接受 Claim 上，需在迁移时改为章节小节。SQLite 默认 `unicode61` 对连续汉字按字符类别成词，`trigram` 的全文查询不匹配不足三个字符的短词；中文短词还需别名与精确匹配。依据：[SQLite FTS5 官方文档](https://www.sqlite.org/fts5.html)。
- 用户确认：语义索引只处理当前发布最新章节的已发布正文；小节超过模型输入上限时按段落切成有界片段，片段只用于召回，返回稳定小节 ID 并按小节去重。
- 用户确认：问题编号、配置键与路径的精确命中优先；全文与语义候选合并。搜索结果给命中方式、实际正文片段与来源范围，不把相似度显示为事实可信度；软件版本适用性仍交 `get_topic` 判断。
- 用户确认：本地模型缺失时词法搜索继续可用，并明确标示语义检索不可用；M1 验收仍须证明固定模型能在离线环境中召回代表性的词法漏检。

## Resolution comment

M1 保留本地 embedding 混合检索为必交付项。`search_knowledge` 在一个固定知识发布内，只搜索每个产品与主题当前最新章节的小节；历史章节由 `get_topic` 按版本读取。索引包含小节标题、正文、固定调查问题编号与问法、配置键和路径。产品与主题别名、问题编号、配置键和路径提供精确入口；全文检索补充词法召回，中文短词不依赖默认分词器独自处理。

语义索引只从上述已发布小节文本建立，不纳入来源原件、审计、未发布候选或历史章节。小节过长时按段落切成模型可接受的片段，片段带所属小节身份；查询合并精确、全文与语义候选，稳定去重为小节结果。精确问题编号、配置键和路径优先。结果给稳定 `section_id`、命中方式、来自正文的片段、章节来源范围和 `release_id`；相关性只用于搜索排序，不表示结论可信度、软件版本适用性或产品优劣。`search_knowledge` 不接收安装版本筛选；Agent 用 `get_topic` 读取正文并核对版本与条件。

模型及其索引绑定知识发布，固定身份与本地文件，构建和查询不临时下载。模型或索引不可用时，词法结果仍可查询，响应须明示语义检索不可用；这种降级不算完成 M1 混合检索验收。M1 验收使用代表性的中英查询，证明离线语义召回确实补足词法漏检，同时保持发布、来源、分页和版本边界。具体模型与推理依赖在真实章节语料就绪后选择并锁定，不在此票预定。

现有 Claim FTS、指南字符串搜索及 PRD 的 Claim embedding 规则由[“确定现有实现迁移与 OpenSpec 修订边界”](09-migration-handoff.md)安排替换。
