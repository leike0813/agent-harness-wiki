# 定义文档站的页面组织与阅读样例

Type: prototype
Status: resolved
Assignee: codex
Parent: [重新确定知识库交付与维护契约](../map.md)
Blocked by: [细化七类主题的调查问题与章节内容](04-topic-contract.md)

## Question

站点的产品页、主题页与小节应怎样导航、展示配置步骤和代码例子、标注源码提交/文档快照及来源冲突，才能让读者直接解决配置问题？用一页 Codex Skills 和一页闭源产品主题草样，请用户确定页面契约。

## Discussion

- 用户否定“首屏答案/配方”与“问题短答卡片”两种结构，要求按 Wiki 或项目文档写作：正文先按章节陈述事实，页末在来源之前可放少量 Q&A。
- 已据此重排[Codex CLI 与 Claude Code 的页面草样](../site-page-prototype.md)。

## Resolution comment

用户确认以 Wiki／项目文档组织站点：产品概览下每个主题独立成页；正文按产品机制分章陈述事实和配置例子，页内有稳定锚点，搜索可直达章节。Q&A 仅在有实际使用或排错问题时出现，置于正文之后、来源之前，不能替代主体章节。

页首简要标明所跟踪的源码提交或官方文档快照，正文相关章节标来源，页末集中列可打开的定位。来源冲突与未查明项放在受影响章节，不以整页 `partial` 标签压过可用内容。默认展示当前已发布的调查结果；历史入口提供该主题过去的知识发布及对应来源版本，不把来源版本写成已验证的安装包版本。

页面阅读顺序与开源／闭源来源的示例见[文档站 Wiki 页面草样](../site-page-prototype.md)。这份草样是规划资产，不作为已发布的 Codex 或 Claude Code 知识。
