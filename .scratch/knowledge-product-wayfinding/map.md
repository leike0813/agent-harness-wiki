# 重新确定知识库交付与维护契约

Label: wayfinder:map

## Destination

形成经用户确认、足以修订 PRD 与 OpenSpec 的产品契约：明确文档站的主题内容、MCP 的工具与响应、以源码和官方文档为主的调查及更新流程，以及备用二进制与隔离环境的职责。契约应能指导现有实现的迁移，不再让实施 Agent 自行决定知识内容和验收口径。

## Notes

- 这是对[原项目规划地图](../project-wayfinding/map.md)的产品方向复议；旧地图保留决策历史，旧格式 release 无向后兼容要求，旧决策不自动约束新契约。
- 讨论时使用 `grilling` 与 `domain-modeling`；涉及页面或接口形态时给出具体样例供用户判断。
- `reader-guides-20260929` 的大章节结构和问题覆盖已获用户认可；具体表述风格、章节细分与内容深度仍待讨论。工作区已有未提交改动；规划阶段不改动或丢弃它们。
- 议题记录决策，产品规格与代码修改在地图完成后另行实施。
- 产品契约已用于修订 PRD 与 OpenSpec；补充的成稿尺度决定见下方索引，供后续章节修订采用。

## Decisions so far

- [确定知识库的交付物与主题主稿](issues/01-delivery-and-chapters.md)：文档站和 MCP 共用以主题章节为主的知识；七类共同导航配各产品的具体问题清单。
- [确定 Agent 调查、复核与发布政策](issues/02-agent-publication.md)：固定源码或官方文档是主要依据；Agent 可直接采纳结论，按需由另一 Agent 复核，不设人审门禁。
- [确定备用二进制的职责](issues/03-managed-binaries.md)：各产品保留最新受管二进制及隔离环境，做无付费服务的最小启动检查；它不决定知识是否可发布。
- [细化七类主题的调查问题与章节内容](issues/04-topic-contract.md)：确定 53 个可定位的必答问题、来源与示例规则，允许产品专有小节及局部未查明项。
- [定义文档站的页面组织与阅读样例](issues/05-site-presentation.md)：产品 × 主题独立 Wiki 页，正文按机制分章，Q&A 位于页末来源之前，来源与历史范围可查。
- [确定 MCP 工具参数与返回契约](issues/06-mcp-contract.md)：五个只读工具围绕章节、小节、问题定位和固定来源工作；版本可向前近似匹配并明确标出适用边界，当前发布索引可查询的历史章节。
- [定义上游变化到新知识发布的细则](issues/07-update-workflow.md)：手动检查三类上游身份，按问题和小节调查影响；冲突按需独立复核，校验通过后自动发布已完成内容，审计保留阻塞与历史。
- [定义最新二进制与隔离环境的维护方式](issues/08-binary-environment.md)：按登记 npm 渠道更新候选包，禁用安装脚本并直接运行锁定入口；在 Linux 沙箱做离线启动检查，成功才切换，失败保留旧环境且不阻断知识发布。
- [确定结构化知识的最小模型](issues/10-knowledge-model.md)：不可变主题章节 Markdown 与问题索引为主稿；独立来源引用及版本映射，发布清单索引当前和历史章节，Agent 审计取代逐条接受门禁。
- [确定搜索与本地 embedding 的定位](issues/11-search-policy.md)：M1 必须提供最新章节小节的离线混合检索；精确与全文入口优先，语义片段归并到小节，结果保留来源边界与降级状态。
- [确定现有实现迁移与 OpenSpec 修订边界](issues/09-migration-handoff.md)：改写现有 `m1-reader-guides`，五项 change 分阶段验收；旧格式 release 不做兼容，新发布内保留历史章节索引。
- [确定知识章节的表述风格与细分尺度](issues/12-chapter-writing-granularity.md)：按读者机制分节；配置文件及适用的目录、命令、Hook 和优先级规则给有来源、带解释的实例。
