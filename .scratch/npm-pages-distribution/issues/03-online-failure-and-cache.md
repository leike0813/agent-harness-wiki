## Question

在线读取是否使用进程内缓存或跨进程缓存，缓存怎样绑定固定知识发布并限制体积？首次启动断网、读取超时、资源不存在、数据损坏或不兼容、请求被限流以及调用取消时，CLI 与 MCP 分别返回什么结果？

区分正常知识缺口与技术失败。明确启动阶段与工具调用阶段的等待边界、必要的重试及旧缓存可否使用；不能在一轮查询中静默切到另一个知识发布。用“新发布出现后旧进程继续读取”和“部分请求失败”的情形检验政策。

## Inputs

- [词法搜索决议](02-online-lexical-search.md)已确定资源处理预算和超限语义；本议题补齐请求时间、数量／并发、缓存与错误转换，不以缓存命中绕过处理预算。
- 搜索分页可以重算且不依赖查询会话；正文与来源按需读取，并始终绑定启动时确定的发布。缓存应改善速度，不成为知识真源或跨发布混用的理由。

## Answer

### 在线与离线启动

默认在线启动在总体30秒内重新确认 `current.json`，读取并校验所指发布清单与产品目录，初始化成功才开放工具。指针不可达、协议不兼容或初始化必需资源失败时明确退出，不自动采用上次发布并声称已确认当前发布。

确认指针后，固定发布的已校验资源可从内存／磁盘缓存读取，不要求重新下载。MCP进程和一次CLI查询始终绑定初始化所得发布；即使current切换、网络断开或旧发布从站点删除，也不能在调用中自动改用另一发布。缓存足够的调用仍可完成，缺必需资源的调用明确失败。

提供显式 `--offline` 模式，从同一数据入口与协议命名空间下最近一次成功初始化记录选择发布，校验缓存的清单和目录后开放工具。该模式不发起网络请求，响应注明离线与 `knowledge_published_at`，仍保留 `release_id`。离线标识表达主动采用缓存发布，不用于标记默认在线调用的一次缓存命中。

最近成功初始化记录只在清单和产品目录均校验通过后更新，不能因刚收到新current就覆盖。缺记录或任一查询必需缓存时返回 `offline_cache_miss`；缓存损坏则明确返回缓存数据错误。不承诺完整离线知识，不预取全库，不访问上游补齐缺口。

支持关闭文件缓存与指定缓存目录；具体选项名称与三个平台默认路径由npm交接统一。关闭文件缓存不能秘密恢复其读取；无初始化缓存时离线启动明确失败。

### 缓存责任与容量

缓存键绑定标准化数据入口、协议、发布身份和资源相对位置。只缓存按需取得、校验通过的已完成资源，不缓存网络错误、残缺下载或未校验内容。

| 项目 | 首版约束 |
| --- | --- |
| 内存缓存内容 | 32 MiB，以保留的解码资源内容计；不是整个进程内存／对象开销上限。 |
| 文件缓存内容 | 128 MiB目标上限，优先回收较久未使用的资源。 |
| 固定发布资源 | 不按时间过期，按容量回收，读取时核对结构和身份。 |
| 当前指针 | 每次默认在线启动重新确认，旧指针或最近成功记录不替代在线确认。 |
| 缓存写入／回收失败 | 作有界诊断，仍可返回已校验在线结果。 |

回收后离线可能缺资源，这是按需缓存的边界，不派生为unknown／not_investigated。缓存不是知识真源，资源不会因年龄变成另一发布。

落盘采用同目录临时文件，完整取得并校验后原子安装，读取方不得看见半个JSON。只在本程序拥有的缓存命名空间内回收，不覆盖用户无关文件，不引入缓存数据库或持续清理服务。多进程同时写入／回收可能短暂超过128 MiB目标，回收后尽量收敛；不把目标上限声称为跨进程严格磁盘配额。

损坏或身份不符的缓存不可使用：在线重新获取同一固定发布资源，离线明确失败。损坏网络数据不可进入缓存，不作为正常空结果。活动查询已取得的对象不因缓存回收失效。

只要求复用已完成资源，不要求跨调用合并尚未完成的下载；不同调用各自拥有取消生命周期，取消一个调用不能中止另一个调用需要的工作。

### 时间、数量和并发

| 边界 | 首版值与口径 |
| --- | --- |
| 初始化总时间 | 30秒，不包含npx下载npm包。 |
| 普通调用总时间 | 每次30秒，包含排队、正文读取、重试等待、校验与结果组装。 |
| 单次HTTP | 10秒，包含完整正文读取，且不超过调用剩余时间。 |
| HTTP并发 | 每进程最多4个活动请求，多个调用共享上限。 |
| 每调用资源数 | 最多64个不同资源，缓存也计，同一资源重复引用只算一次。 |
| 每资源网络尝试 | 最多两次GET；重试不增加不同资源数，但计入总时间。 |

搜索的2 MiB索引、20,000个过滤后排序候选、8 MiB当页章节预算同时生效。资源数或查询规模超限返回 `query_too_broad`，不自动删来源／候选或改变页大小以假装成功；响应大小仍按既有MCP边界处理。

总截止期限不因进入下一阶段或取得部分资源重新计时。取消传递到排队、HTTP、正文读取和退避等待；校验／组装／排序等处理中按有界批次检查取消与期限，避免长时间同步处理阻塞取消。服务断连／退出取消未完成工作。

[检索能力决议](05-optional-semantic-search.md)确定发布版MCP不提供语义检索，普通调用按本票词法预算执行；该预算不声称覆盖仓库现有本机Ollama调用。

### 重试与局部失败

幂等在线GET遇网络中断、单次请求超时或HTTP408／429／502／503／504时最多重试一次。普通重试短暂退避；有效 `Retry-After` 按秒数或HTTP日期等待。若等待超过剩余总时间，不提前违反服务器要求重试，直接报告相应故障。依据：[RFC 9110 §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3)。

401／403／404、协议不兼容、发布身份错误和损坏数据不自动重试。取消和总体超时不再重试。重试仍访问相同发布的相同资源，不重新解析current、不自动重启查询或退旧版。`retryable` 表达故障性质和调用方之后可否再试，不表示突破两次／30秒限制。

比较一个必需目标或搜索一个必需索引读取失败时，本次调用整体失败，不返回部分数据冒充完整比较／完整排序。失败不退出MCP进程、不影响独立调用。网络故障与缺失发布资源不能翻译成正常知识状态。

### 来源存在性与404

构建器从同一发布所有保留章节引用与目录身份来源生成轻量目录：

```text
sources/index/index.json
sources/index/blocks/<block-id>.json
```

根入口按引用ID范围定位分片；每项仅需 `reference_id` 与 `harness_id`，用于判断存在性和可选界面所属产品。目录不携带完整来源正文，也不将全量引用或文件库存塞入发布清单。资源布局回写在线契约，错误政策集中保留于本议题。

| 情形 | 结果 |
| --- | --- |
| 校验通过的目录证明ID未登记 | 正常 `not_found`。 |
| 目录证明主题不存在／章节证明小节不存在 | 保留既有正常知识结果，不靠HTTP错误推断。 |
| 已登记来源文件404 | `release_resource_missing`，技术错误。 |
| 清单、必要导航、已声明主题索引或章节404 | 技术错误，不认为发布没有知识。 |
| 判断存在性所需目录读取失败 | 技术错误，不能断言引用不存在。 |
| 离线缺必要目录或来源文件 | `offline_cache_miss`。 |

结果不能依赖调用方此前是否看过引用。目录涵盖保留历史章节及候选产品身份来源；构建校验每个ID的文件存在与所属产品一致，查询不访问上游补证。

### CLI与MCP错误契约

QueryService生成统一项目技术错误，CLI和MCP只适配。错误包含稳定代码、简短原因、已绑定发布身份（如已有）和故障可重试性；HTTP状态可作结构化诊断。消息不是机器判断契约，不附用户路径、完整环境或来源原件。

MCP技术错误返回 `isError: true`，结构化内容与文本表达同一错误；stdout只用于协议。CLI技术失败非零退出，诊断写stderr；JSON模式stdout输出同一结构化错误。缓存读写失败只作有界诊断，不使已成功在线查询失败。

正常unknown／not_found／not_investigated／ambiguous／冲突仍是领域结果。[自动发布决议](04-automatic-publication.md)新增的`history_not_available`也是正常领域结果，不是网络失败；裁剪标记与旧协议退役提示必须由明确元数据判断，不能靠404猜测。既有 `response_too_large` 受限结果与小节定位提示保留，不混同网络缺口。

| 代码 | 含义 |
| --- | --- |
| `offline_cache_miss` | 显式离线缺初始化或查询必需缓存。 |
| `invalid_cached_data` | 必需缓存损坏／身份错误，当前模式无法恢复。 |
| `network_error`／`request_timeout` | 网络失败或单次HTTP超时。 |
| `operation_timeout` | 调用总体期限已到。 |
| `rate_limited`／`http_error` | 限流或其他HTTP技术失败。 |
| `release_resource_missing` | 固定发布已声明的必需资源缺失。 |
| `invalid_release_data`／`unsupported_protocol` | 网络发布内容不合法或协议不可解析。 |
| `query_too_broad` | 字节、候选或不同资源数超限。 |
| `invalid_cursor` | 发布、规范化查询、实际词项、排序或位置不匹配。 |

取消遵循MCP SDK协议：对方已撤销请求时不强制补发错误或成功包。CLI取消中止工作并非零退出。工具层须使用SDK已有 `ctx.mcpReq.signal` 传递取消，不能只依靠SDK丢弃响应而让下载继续。

### 情形核对与实施验收

- current从A切到B：旧进程仍读A，新进程确认B，不拼接两者。
- 新清单／目录失败：初始化失败，不更新最近成功记录，不自动采用A。
- 默认启动断网：失败；显式离线仅在有必需缓存时启动并标识发布与模式。
- 离线启动后缺某章节：该调用缓存缺口，目录等其他可完成调用仍可用。
- 缓存写失败：返回已校验在线结果，下一次可能重新下载。
- 未登记引用与已登记文件404：分别是正常缺口和技术错误，不依赖调用历史。
- 搜索必要块／比较一个目标失败：本次整体失败，进程继续服务。
- 一个调用取消或服务关闭：停止其排队／下载／重试，独立调用不受单次取消影响。

规划期完成的是来源ID目录体积测量、已安装SDK类型／实现只读核验和文档链接／依赖检查。尚未实现在线缓存、截止期限、并发限制、结构化技术错误或离线模式；没有执行这些功能的端到端测试。

实施必须覆盖上述可观察行为，以及多进程半写／损坏恢复、容量回收、只读缓存目录、超时／429／Retry-After／404、真正stdio取消／断连、CLI JSON错误及三个平台路径。默认验收使用受控本地HTTP与临时缓存，不访问真实HOME或要求公网；实际Pages与真实npm安装另作显式交付验收。
