# 确定在线读取的数据契约与分片粒度

Type: grilling
Label: wayfinder:grilling
Status: resolved
Assignee: codex
Parent: [确定 GitHub Pages 与 npm 在线知识分发规格](../map.md)

## Question

Pages 应发布哪些机器数据，以何种粒度组织产品目录、主题与章节版本、可检索小节、问题答案、来源引用和软件版本映射？客户端如何在启动时选择兼容的知识发布，并使整章读取、小节读取、比较及来源查询都能按需获取数据，而不下载全库或解析 HTML？

明确发布身份与数据协议身份、读取入口与资源定位、各操作所需的数据范围，以及客户端与站点如何共享同一知识内容。用一次“搜索、读小节、读来源、比较”的连续调用样例检验契约；不在此议题选择搜索算法或缓存政策。

## Discussion

- 本议题通过三轮用户确认达成决议，详见下方 Answer。搜索算法、缓存和失败政策由后续议题处理。
- 当前五工具的版本解析、问题与界面状态、来源和响应限制以 PRD §5 为依据。比较当前通过完整章节获得问题答案；在线形式可调整读取方式，但不因此改变比较含义。
- 对当前发布 `catalog-surfaces-20260930-v1` 的紧凑 JSON 内存投影统计：42 篇当前章节合计 506,179 字节，中位 8,529 字节，最大 46,553 字节；226 个当前小节正文最大 6,897 字节。以上不是最终 HTTP 资源大小，不含响应信封及压缩。
- 同发布含 610 条章节来源引用；按产品整包读取的紧凑 JSON 最大约 176 KiB。按来源引用单独读取可避免为一个来源下载整个产品的来源集合。
- 首轮待用户选择：章节或小节的正文资源粒度、来源资源粒度，以及是否沿用现有五工具的领域语义。资源定位和数据协议兼容性待首轮结果后继续细化。
- 用户确认首轮全部推荐：每个章节版本一个正文 JSON 文件，读取小节时从该章节提取；每条来源引用一个 JSON 文件，保留固定快照身份、官方链接、定位与短摘录；沿用五工具的输入及版本、界面、问题状态、来源、分页和响应大小语义。具体资源路径尚未确定。
- 用户确认第二轮全部推荐：启动读取当前发布指针、该发布清单和产品目录，固定 release_id；主题索引只保存当前章节、历史章节及软件版本／界面到章节的映射和资源位置；问题答案、小节元数据和正文仍在章节 JSON 内。数据协议主版本独立于 npm 程序版本、知识发布和被调查软件版本，URL 以 data/v1/ 分区；不支持的协议明确报错。旧协议和发布保留规则由自动发布议题处理。
- 覆盖检查发现两个需确认的读取边界：list_harnesses 的主题与界面覆盖摘要是否由构建器投影进目录，以避免列目录时读取所有章节；在线清单是否只描述协议和资源入口，由构建端完成整库校验，客户端只校验实际读取的资源。
- 用户确认第三轮全部推荐：产品目录携带由当前章节派生的主题列表和界面覆盖摘要；在线清单保持精简，完整发布一致性由构建端校验，客户端校验实际读取资源的结构、发布身份与请求对象身份。文档和 JSON 从同一份已校验知识生成。
- 用户在[缓存与失败议题](03-online-failure-and-cache.md)确认补充来源存在性目录，按ID范围分片、只保存引用ID与所属产品，避免把缺失文件404当引用不存在；本契约已同步补充资源布局和get_source依赖，错误政策集中保留在该议题。

## Answer

### 身份与读取入口

在线数据协议首版使用 `data/v1/`。协议主版本、npm 程序版本、知识发布 `release_id`、章节版本 `edition_id` 和被调查软件版本具有独立含义；普通知识更新不要求发布新的 npm 包。

```text
data/v1/current.json
data/v1/releases/<release-id>/manifest.json
data/v1/releases/<release-id>/catalog.json
data/v1/releases/<release-id>/topics/<harness-id>/<topic>/index.json
data/v1/releases/<release-id>/chapters/<edition-id>.json
data/v1/releases/<release-id>/sources/<reference-id>.json
data/v1/releases/<release-id>/sources/index/index.json
data/v1/releases/<release-id>/sources/index/blocks/<block-id>.json
```

客户端以站点的数据入口为起点，顺序读取当前指针、所指发布清单、产品目录，完成校验后开放查询。MCP 进程内固定这一个 `release_id`；后续章节、来源及搜索资源都在该发布内读取。重启解析新的当前发布。查询 CLI 的一次运行采用同一绑定原则。

站点可位于项目子路径；资源位置按数据入口／发布清单所在 URL 解析，不假设站点在域名根目录。路径中的身份使用已有 ID 约束，不向 MCP 暴露任意 URL 或文件读取入口。

指针和清单声明协议主版本与发布身份。清单还包含 `knowledge_published_at` 和资源入口；其他资源携带 `release_id` 及可验证的对象身份。沿用领域记录各自的 schema 版本，不能把领域 schema 版本当作数据协议版本。不支持的协议明确失败，不尝试猜测解析。

### 资源的职责与内容

| 资源 | 内容与边界 |
| --- | --- |
| 当前指针 | 当前兼容协议分区下的发布身份和清单入口；不携带章节或搜索数据。 |
| 发布清单 | 协议、发布身份、发布时间和资源入口；不列全库正文、全部来源、历史章节或完整文件清单。搜索入口的具体形态由词法与语义议题补充。 |
| 产品目录 | 产品 ID、名称、别名、来源引用 ID、界面、运行时与绑定状态，登记状态、当前主题列表及界面主题覆盖；支持现有 registry/catalog 两种目录范围。 |
| 产品 × 主题索引 | 当前章节版本、同主题保留的历史章节版本及其资源定位、软件版本／界面到章节版本的映射。映射保留 chapter/section 范围与证据引用，不复制问题答案或正文。 |
| 章节版本 | 一个完整章节的标题、正文（含引言）、小节范围、逐题答案和状态、来源引用 ID；携带生成查询结果所需的来源范围摘要，包含引用 ID、快照 ID 和官方 URL。摘要由同一来源记录投影，不单独维护。 |
| 来源引用 | 每条引用一个文件，保留固定快照身份、官方 URL、定位和短摘录；覆盖章节引用和目录身份来源这两类既有记录。读取该文件不读取来源原件。 |
| 来源存在性目录 | 由同一发布全部保留引用生成，按ID范围定位分片，只记录引用ID和所属产品；按需判断ID是否存在，不携带全部来源正文或文件库存。错误语义见[缓存与失败决议](03-online-failure-and-cache.md)。 |

目录覆盖摘要由构建器从当前章节答案派生；候选产品、无章节主题和声明但未调查的界面仍按现有规则表达。目录不承载完整来源摘录。原 `catalog/harnesses.yaml` 及结构化知识继续作为真源，在线目录不成为第二套手写登记。

每个章节版本一个 JSON 文件，不拆小节正文资源。小节查询读取选定完整章节，在客户端提取目标小节；保持正文和元数据来自同一个章节版本。比较直接读取参与比较的章节，无专用答案数据库或比较投影。

历史章节的可定位数据与当前章节共同保留在对应发布的主题索引中；列出历史不要求读取全部历史正文。在线保留范围、被裁剪章节的轻量选版标记及结果，按[确定自动发布与历史资源保留规则](04-automatic-publication.md)执行；主题索引须区分可读章节与裁剪标记，不能为标记生成正文资源入口。现有 `get_topic` 不增加 `edition_id` 输入；版本选择继续通过现有软件版本映射和查询契约完成。

### 五工具的读取关系

| 工具 | 启动之后所需资源 |
| --- | --- |
| `list_harnesses` | 已读取的产品目录；不读取所有主题和章节。 |
| `get_topic` | 产品 × 主题索引和选定章节；小节从同一章提取，来源范围从章内摘要取得。 |
| `search_knowledge` | 后续议题确定的搜索资源；结果定位到当前章节的小节，保留发布、界面、来源范围、预览及现有分页语义。 |
| `compare_topics` | 各目标的主题索引与选定章节，按现有问题 ID 和界面答案对齐，保留各目标自身的版本解析与状态。 |
| `get_source` | 按需读取来源存在性目录，确认ID与所属产品后读取对应来源 JSON；可选界面的合法性以产品目录核对。 |

保留现有五工具的输入和领域语义，CLI 与 MCP 调用同一查询服务。内部读取可以变为异步，协议入口不重复实现版本选择、问题状态或来源判断。

以下行为不能因在线分发改变：带软件版本读取必须指定界面；来源快照不证明软件发行版；映射缺失不能生成已验证结论；声明但未调查的界面派生为 `not_investigated`；正常知识缺口不当作协议故障；分页绑定发布及规范化查询；摘录、分页和 MCP 响应大小保持有界。

### 连续调用示例

以下 `r`、`e`、`s` 和 `ref` 是调用中取得的身份占位符，不是新增查询输入。

1. MCP 启动读取 `current.json`，确定发布 `r`，读取其清单和产品目录。即使站点稍后指向另一个发布，该进程继续访问 `r`。
2. 调用 `search_knowledge({text: "MCP", harness: "codex", topic: "mcp"})`，按搜索方案读取 `r` 内的索引，返回当前章节 `e` 的小节 `s`、界面和来源引用定位；不预读其他产品或所有章节正文。
3. 调用 `get_topic({harness: "codex", topic: "mcp", surface_id: "cli", section_id: s})`，读取该主题索引和选定章节 `e`，提取小节与相关问题答案，返回来源范围；无需逐条读取来源文件才生成范围摘要。
4. 调用 `get_source({reference_id: ref, surface_id: "cli"})`，在 `r` 的来源存在性目录定位引用后读取对应来源文件，得到固定快照身份、定位及短摘录，不跟随官方链接访问上游。
5. 调用 `compare_topics({topic: "mcp", targets: [{harness: "codex", surface_id: "cli"}, {harness: "claude-code", surface_id: "cli"}]})`，读取两个目标的主题索引及各自当前章节，在 `r` 内按问题比较。没有提供软件版本，不将当前调查版声称为已验证的安装版本。

该示例描述资源依赖，不承诺缓存命中、请求次数、并发顺序或搜索算法；这些由对应后续议题确定。

### 发布与校验责任

文档站页面和在线 JSON 由同一份已校验知识、同一个发布身份生成。在线文件是结构化真源的构建投影，不通过读取 HTML 或从生成 Markdown 反向抽取事实形成数据。

完整引用关系、章节选择、软件映射、目录覆盖、来源摘要与真源一致性，以及 fixture/production 隔离，由发布构建校验。客户端不执行当前本地 `verifyChapterRelease` 那种需要整库文件、SQLite 和文档的完整验证；它在每次读取时校验资源结构、绑定的发布和所请求对象。失败不能返回假成功或静默混用发布。

在线契约须通过正式构建与新规格实现；不能删减当前本地发布文件、绕过其 manifest 校验，再以原发布身份声称在线发布完成。现有离线查询及生产语义索引要求的调整留给规格交接明确记录。

### 后续议题边界

- 词法搜索议题确定搜索资源的内容、分片、体积和分页实现；本议题不选择搜索引擎。
- 缓存与失败议题确定超时、重试、取消、缓存和技术错误表达，尤其区分已知资源缺失与正常不存在的引用，不把 HTTP 错误自动翻译成知识结论。
- [自动发布决议](04-automatic-publication.md)确定构建触发、完整发布上线与当前指针切换、旧发布／协议／历史章节保留，以及有限历史的正常业务结果和退役提示；公共Schema／DTO由交接规格落实。
- [检索能力决议](05-optional-semantic-search.md)确定发布版MCP不提供语义检索；消费者CLI与依赖边界由交接票明确。
- npm 分发与交接议题落实消费者入口、正式 DTO/Schema、包内容、平台验收和 PRD/OpenSpec/ADR 更新。本次只完成规划决议，没有实现、部署或发布。
