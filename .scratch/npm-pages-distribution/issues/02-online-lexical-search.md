## Question

在 Pages 只托管静态文件的前提下，词法搜索如何保留产品与主题别名、问题编号、配置键、路径和中英正文的召回，并支持有界的全局及过滤查询？搜索索引怎样生成、组织和按需获取，才能避免随着 harness 和历史章节增长而每次下载全部正文？

明确返回小节、预览、来源范围、命中方式与分页的含义，以及索引体积和单次读取的规模边界。优先复用成熟方案，但用实际可验证的搜索行为判断选择；将需要的官方资料调查和小样验证作为本议题的依据。

## Answer

### 首版检索范围与实现

首版公开消费者使用 JSON 倒排索引和 Node 原生分词，复用当前章节构建、小节定位、精确配置词与路径提取、问题编号／问法和别名。索引只覆盖所绑定发布的当前小节；历史正文仍通过主题索引与既有版本映射读取，不参与默认搜索。

不以全量 `search.json`、SQLite 文件或全部章节作为在线搜索的首次下载。不依赖 MiniSearch 私有索引格式；不以尚未验证的 Pagefind 浏览器 runtime 适配作为首版默认实现。此决议不影响维护者侧现有 SQLite 构建用途，消费者包依赖范围由 npm 交接议题落实。

精确入口保留问题编号、配置词／路径、完整问题问法和别名。配置符号与路径整体参与匹配，不能只交给会拆标点的词法分词器。词法入口包含标题、正文与问题问法，支持中文词语／短语和英文关键词组合；不承诺任意字符子串、拼写纠错或同义理解。当前全文 `includes` 行为的调整须明确进入 PRD／OpenSpec，而不是声称线上分发完全保留旧召回。

自然语言问句可输入词法入口，但不保证语义召回。无匹配保持正常空结果，不解释为能力不支持。发布版MCP的检索范围见[检索能力决议](05-optional-semantic-search.md)；本次不改变问题状态、证据或软件版本判断。

### 资源结构与定位

搜索资源全部位于固定的 `data/v1/releases/<release-id>/` 内，由前一议题的发布清单指向搜索入口。以下是交接采用的布局；块编号只用于定位构建产物，不进入工具输入。

```text
search/manifest.json
search/exact/index.json
search/exact/blocks/<block-id>.json
search/lexical/index.json
search/lexical/blocks/<block-id>.json
search/scopes/<harness-id>/<topic>/index.json
```

| 资源 | 职责 |
| --- | --- |
| 搜索清单 | 绑定发布、搜索格式／分词／排序规则版本、预算及索引入口，不带全库正文。 |
| 精确／词法导航 | 以排序词项的首尾范围定位相关块，携带可剪枝的产品／主题范围和资源位置。导航过大也按范围拆分，根入口不要求加载全部词项字典。 |
| 词项关联块 | 词项到当前小节的关联片段，携带稳定小节定位、界面范围及排序需要的匹配类别／字段信息。产品和主题可由范围头共享，避免为每条关联重复完整身份。 |
| 范围小节目录 | 当前产品 × 主题的小节定位与界面范围，以稳定 ID 预排序，不含正文；用于只有过滤条件的查询，不扫描全文倒排。 |

按照词项排序、按字节打包，目标每块约 64 KiB；单个热门词的关联列表也可以跨块。所有分片必须完整重组、去重，不能以单个词项过长为由截断。块与导航携带实际结构校验和发布身份；块大小属于构建和读取边界，不是可信度指标。

全局文本查询从查询词定位相关块，不逐个扫描产品；有产品／主题约束时依据导航和关联片段的范围尽早跳过不相关资源，界面过滤在排序前完成。无需全量下载一个数字小节 ID 到产品／主题／章节的全局定位表才能完成过滤。

只有产品或主题过滤、没有文本时，读取对应轻量小节目录，沿固定 ID 顺序定位页窗口；不为排序下载全部正文，不读取所有词项块。指定界面后只返回该界面的小节；候选产品和声明但未调查的界面沿用既有状态表达。

### 查询、排序与结果

一次文本查询的步骤为：规范化输入和产品别名 → 获取精确／词法关联并按范围筛选 → 小节去重 → 检查预算 → 确定性排序 → 取页窗口 → 按需读取当页章节 → 生成预览与来源范围。

沿用精确问题编号、配置词／路径、完整问法、别名优先的类别顺序，再进入正文词法命中。同级候选按不同关键词的覆盖数量及命中字段权重排序，最后按稳定章节／小节 ID 打破平局；使用固定比较规则，不将宿主区域排序作为契约。排序规则具有独立版本，具体字段权重由共享规则声明，不在 CLI 与 MCP 重复维护。

多词全部命中的候选自然先于覆盖较少的候选，较弱候选仍可以排序靠后；不以固定数量的未排序候选截断来冒充完整召回。短语可以按关键词组合检索，不把字符连续子串等同于已承诺的检索契约。相关性不改变知识状态、来源范围或软件适用性。

结果仍提供当前小节的 `harness_id`、`topic`、`edition_id`、`section_id`、界面、问题编号、预览、来源引用及范围、命中类别和发布身份。使用既有 `exact_question_id`、`exact_config_term`、`exact_question_wording`、`alias`、`full_text`、`filter` 的语义，不增加“相关性等于可信度”的含义。

正文命中时，预览取命中词附近的有界实际正文；只有过滤或仅元数据命中时取小节开头。片段不调用模型生成、不拼成另一版本正文。先完成索引排序再读当页章节，不通过读取全部候选正文获得排序；同章多个命中合并为一次资源读取。来源范围直接取已确认的章内来源摘要，完整引用与摘录仍由 `get_source` 单条读取。

保留现有预览长度边界与统一 MCP 响应边界，截取不得产生破损 Unicode。预览不是完整答案，调用方可按小节定位继续调用 `get_topic`。

### 分词与运行环境

构建器与客户端使用同一份分词、文本规范化和排序规则；首版以 `Intl.Segmenter` 的 word 分词为基础，精确入口与词法入口分别处理。共享规则版本写入搜索清单，构建环境的 Node／ICU 信息记录为可诊断元数据。

保留现有产品／主题别名与精确提取规则，不以人工逐词维护所有中文正文作为普通更新步骤。规则不隐式截断输入到前几个词；读取／处理超过预算时明确返回超限。

不依据 ICU 版本字符串完全相同作为硬门禁。对受测的 Linux、macOS、Windows 与 Node 版本执行代表性中文、英文、配置键、路径及分页验证；实际分词能力缺失时明确失败，不静默替换另一算法。不能因 Node 主版本相同就声称任意 ICU 配置的召回逐条一致。

### 分页与预算

cursor 不依赖查询会话或服务端状态；绑定发布、规范化查询、实际规范化词项、过滤条件、排序版本和页位置。下一页可以重算同一结果序列。分词或排序发生改变时，旧 cursor 明确拒绝，不能造成重复／漏页后仍报告成功。

| 边界 | 首版值 | 计量与行为 |
| --- | --- | --- |
| 索引处理数据 | 每次查询 2 MiB | 以解压后的资源字节计，包含搜索导航、关联块及过滤／排序元数据；不以 gzip 小或缓存命中绕过。 |
| 排序候选 | 20,000 个 | 产品／主题／界面过滤后的去重小节，实际参与排序者；不将被剪枝范围计作已排序候选。 |
| 当页章节读取 | 每页 8 MiB | 解码后的章节资源，同一资源在一次页请求内只计算一次；包含正文与章内元数据。 |
| 工具页大小 | 默认 10，上限 20 | 保持已有输入契约，不自动改变调用方指定的分页大小。 |
| MCP 响应 | 128 KiB | 保持结构化内容与文本表示的一致语义及现有响应上限。 |

索引、候选或当页章节预算超限返回 `query_too_broad`，提示缩小产品／主题范围或由调用方调整页大小，不返回截断候选的成功页。响应本身超限沿用响应大小错误契约，不静默删来源或事实字段。

预算按一次查询／页请求实际处理的不同资源计算，与资源来自网络还是缓存无关；相同块被多个查询词引用只算一次。读取时间、请求数量／并发、重试、缓存容量和错误到 CLI／MCP 的具体转换，由缓存与失败议题补齐。

### 实验与实施验收

可重跑实验：[lexical-sizing.mjs](../lexical-sizing.mjs)。它是规划期体积测量，不是生产查询实现。

```text
node .scratch/npm-pages-distribution/lexical-sizing.mjs
node .scratch/npm-pages-distribution/lexical-sizing.mjs 100
```

实际执行且通过的断言：词项分片重组无损、目标块尺寸、精确配置与路径定位。当前 226 小节的简化精确／词法倒排分别约 49 KiB／169 KiB；复制词汇、扩展关联到 22,600 个模拟小节后，分别约 2.39 MiB／18.09 MiB；代表性查询只取部分块。完整数据与口径见 Discussion。

未完成且必须进入实施验收的项目：包含发布信封、范围剪枝与排序字段的实际资源体积；全局与过滤召回和噪声；热门词跨块；仅过滤分页；正文命中附近的原文预览与来源一致性；预算超限不伪装为空结果；发布／查询／实际词项变化拒绝 cursor；三个平台与受测 Node 环境；使用实际 HTTP 数据入口与真正 MCP stdio 的读取链。
