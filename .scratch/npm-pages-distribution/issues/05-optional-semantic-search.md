# 确定可选语义检索的获取与调用方式

Type: grilling
Label: wayfinder:grilling
Status: resolved
Assignee: codex
Parent: [确定 GitHub Pages 与 npm 在线知识分发规格](../map.md)
Blocked by: 02, 03, 04

## Question

在默认在线词法检索的消费者分发中，可选语义检索怎样启用，模型与索引分别由谁提供、如何与知识发布对应，以及怎样有界地读取候选向量？模型或索引不可用时，调用、耗时和结果状态怎样表现？

明确消费者是否需要单独获取模型、是否保留现有 Ollama 方式、哪些场景承诺语义能力，并确认与当前 M1 离线混合检索要求的关系；不得将词法分发称为已通过完整混合检索验收。

## Inputs

- [确定自动发布与历史资源保留规则](04-automatic-publication.md)：默认生产词法与页面构建不依赖语义模型；任何在线语义资源须遵守同发布身份、完整资源校验、旧发布保留、跨CI归档及总容量预算。语义不可绕过默认词法发布边界，也不能以可选语义缺失冒充词法发布损坏。

## Resolution

用户直接指定本议题决议：“发布版MCP不提供语义检索能力”。据此结票，不再为发布版MCP设计可选模型、向量索引或语义调用路径。

## Answer

发布版MCP的`search_knowledge`只提供已确定的词法检索，不提供语义检索，也不要求消费者安装Ollama、下载模型或获取语义索引。工具仍沿用既有小节定位、版本边界、来源及词法预算；没有语义能力是产品范围，不是模型暂时不可用或功能降级。

本决定针对发布版MCP，不自动删除仓库已有本地混合检索实现，也不等于已通过原PRD的M1离线混合检索验收。消费者CLI、程序包依赖及公共搜索状态字段按[确定 npm 分发、验收与规格交接范围](06-package-and-handoff.md)的后续确认执行；不能把消费者边界扩展成所有本地入口取消语义能力。

默认在线知识与页面发布已按词法构建确定，不因本决定新增语义发布资源。后续交接正式修订发布版MCP的能力说明、公共契约与对应PRD／OpenSpec／ADR边界。本次只记录规划决议，没有修改实现、部署或发包。
