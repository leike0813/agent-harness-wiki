Type: grilling
Status: resolved

## Question

“独立环境、不干扰系统自带安装”的最低可验证承诺是什么？请明确对系统安装、用户配置与凭据、工作目录、网络、子进程和资源的边界；哪些操作需要显式许可？

## Resolution

- 范围限于当前 Linux 机器。优先用无需容器镜像的进程沙箱；本机 `bwrap 0.9.0` 已通过最小的隔离进程启动检查，但真实 harness、网络阻断、资源上限和子进程边界仍须在 M1 验证。直接运行 `unshare -Ur true` 在本机失败，不作为默认后端依据。
- 受管制品按精确路径启动，不调用系统同名安装程序，也不运行写入系统目录的安装步骤。只把运行所需制品、fixture 和系统运行库交给沙箱；制品与系统目录只读。单次运行使用临时 HOME、XDG/APPDATA、工作目录和可写临时区，不暴露真实用户配置与凭据。
- 默认断开外部网络，子进程继承同一隔离边界；设置并验证超时、输出上限及可行的 CPU、内存、进程数限制。需要本地 mock 服务或外网的实验，单次明确指定允许的网络范围。访问额外宿主目录或改变系统安装均需逐次明确授权；真实凭据不作为默认探针输入。
- 若落实上述强隔离必须引入容器化方案，用户接受改用环境变量与临时目录隔离，但该模式必须明确标为较弱：它不能阻止程序访问宿主文件或网络。只能对手动选择、可信来源的制品运行，不能把这种运行结果表述为沙箱验证。何人能触发执行及制品准入在“确定真实二进制探针权限”议题中继续决定。
- M1 的验收包含一个精确绑定版本和 hash 的真实二进制在所选环境中完成启动 smoke；记录隔离模式和可验证边界。行为探针仍按证据需要触发，不作为每项知识的强制门槛。
