## Question

M1 首批真实 harness、精确版本、分发渠道和平台应如何选取？六类核心主题与横切配置机制应按什么顺序调查，哪些可以诚实地标为 unknown 或 blocked？

## Comments

- 用户同意首批接入 Codex CLI、OMP 和 Claude Code。
- 用户同意三个对象均建立六类核心主题及横切配置的覆盖记录；先深入调查 Skills、MCP 和配置优先级，其余主题可按证据标为 `unknown` 或 `blocked`。
- 用户指定实际运行范围为当前平台，不需要跨平台验证。
- 用户指出文档和源码能给出证据时，无需把行为探针设为默认步骤；二进制可运行与事实必须经探针证明是不同要求。

## Answer

M1 首批接入 Codex CLI、OMP 与 Claude Code。每个对象在接入时核验官方来源，并选定一个精确版本、分发渠道和制品身份；版本号、来源快照与 hash 随接入记录固定，不在规划时写入会随上游变化的“最新版”。

对三个对象都建立六类核心主题及横切配置的覆盖记录，优先形成 Skills、MCP 与配置优先级的精确 Target 事实。其余主题在证据不足或尚未调查时明确标记 `unknown`、`partial` 或 `blocked`，不填充推测结论。

实际运行与验收限当前开发平台（目前为 Linux x86_64）；不设跨平台运行验证目标。若知识中包含其他平台的文档或源码结论，必须保持其 Target 与证据类型明确，不能写成已在当前平台观察到的行为。

首个行为探针不预先指定。文档或已可靠绑定的源码足以回答问题时，无需探针；证据冲突、发布制品绑定不清或行为只能通过运行确认时，再选择对象和具体探针。

后续[界定 harness catalog 的分期与完成标准](14-harness-catalog-phases.md)将 M1 首批对象扩为五个，并要求五个对象均深查三项、尝试独立环境启动；本议题保留初始决策记录。
