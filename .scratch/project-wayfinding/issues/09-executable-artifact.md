## Question

受管理的可执行制品如何进入、留在和离开项目控制的存储？需如何记录来源、版本、平台、hash、入口与运行依赖，使运行实例绑定到精确制品，同时避免覆盖系统已有安装？

## Resolution

- 用户或受托调查 agent 从已核对的官方来源接入精确版本的发布包，或从固定官方源码 commit 构建。原始包和可执行目录保存在仓库内被 Git 忽略的持久 artifact 区域；Git 跟踪来源、分发渠道、版本、平台、内容 hash、源码绑定依据和本地归档引用。官方发布与本地构建采用不同 Artifact 身份。
- 运行实例以 Artifact hash、入口路径和隔离模式绑定精确制品，使用明确路径启动，不调用系统同名安装程序，也不修改系统安装。解包与准备步骤不默认执行包内安装脚本。制品及必要输入在运行环境内只读，可写状态进入单次运行的临时目录。
- 保存原始包与可执行目录，记录解释器、运行库及其他实际依赖的身份和版本。初期允许只读使用本机运行库；若结论依赖某项运行依赖的特定版本，则固定归档该依赖，并在证据中记录。不能把仅靠本机运行库的实例宣称为完全自包含。
- 已被正式证据引用的原始制品持续保留。未被引用的下载物只作人工清理；清理前检查引用，避免知识仍可查询而对应原始制品已经不可复核。不自动清除本地持久归档。实际备份与恢复办法待首批制品出现后确定。
