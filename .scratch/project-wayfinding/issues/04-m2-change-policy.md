## Question

M2 首先跟踪哪些上游变化，如何把变化映射到需复核的 Claim 与主题？在源码或文档未变而 Target、发布包或条件变化时，哪些结论必须重新验证，哪些只能作为待审核候选复用？

## Comments

- 用户同意首批检查上游源码 commit、官方文档内容与新发布版本。
- `ahw sources scan` 是 PRD §16.4 中的后续命令建议，当前尚未实现；用户选择由自己手动发起检查，不运行定时后台轮询。

## Answer

M2 提供按需运行的上游变化检查，首批覆盖上游源码 commit、官方文档内容和新发布版本。命令名称可沿用 PRD 建议的 `ahw sources scan`，但只有实现后才在文档中列为可用命令。检查可以读取上游，不移动 Git submodule 指针，不直接更改已接受的知识或本地 KnowledgeRelease。

影响分析先利用 Evidence 定位的源码文件或文档段落，以及主题、配置键和已知加载模块的映射，列出待复核的 Claim 与覆盖范围。无法可靠定位、涉及配置入口或构建条件等广泛变化时扩大到相关主题；人工可以发起全量复核。

新发布版本构成新的 Target：旧版本结论保持可查询，新版本在审核前保持 `not_verified` 或相应覆盖状态。文档或源码变化触发复核，不自动撤销旧结论。即使来源内容未变，只要发布包、Target、生效条件或构建选项改变，也不能自动沿用旧版本结论；复用必须有明确依据并形成新的 Assessment。

检查只生成可审查的变化与复核候选；具体调查执行权限和预算由 ResearchRunner 议题决定。
