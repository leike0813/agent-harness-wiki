# Design

## Context

动机和规格范围见 [proposal.md](proposal.md)。本 change 补录已实施的迁移，三个 delta 与迁移前 Git HEAD 到当前主规格的变化一致，保留工作区已有改动。部署值、技术依据及真实验收结果以 [ADR 0008](../../../docs/decisions/0008-managed-package-storage.md) 为准。

主规格已包含本 change 的新增要求。严格验证通过，但 CLI 提示普通归档重放 `ADDED` 会因要求已存在而拒绝。完成剩余空间验收后，归档应使用 `openspec archive migrate-managed-packages-to-nfs --skip-specs`，保留验证并跳过重复规格更新；无需为补录记录撤回现有主规格。本次仅补齐 change，不执行归档。

实现涉及受管更新、来源审计和启动沙箱，三者原先依赖本地包集路径。当前维护假设是一台主机写入，共享目录仅维护者可写，沙箱 UID 65534 可读及执行；pnpm 固定为 11.10.0，本机已具备 bwrap、rsync、getfattr 与 setfattr。

## Goals / Non-Goals

**Goals:** 将包字节与本地身份、索引及控制状态分开，统一路径与权限判定；任何晋升结束后都能观察到一致包集，异常或中断状态可识别并恢复。

**Non-Goals:** 多主机并发写入、NFS 超时强制终止、自行更换挂载选项、自动删除历史、修改 Btrfs 备份策略，以及让知识读取依赖 NFS。

## Decisions

### 统一存储边界，拆分 SQLite 与包字节

`src/sources/managed-storage.ts` 负责配置解析、挂载及权限验证、选中快照定位和晋升恢复，更新与审计复用这一边界。配置不存在时沿用本地布局，配置损坏时报阻塞，避免错误配置导致写入另一套字节。

通过本地四处链接保留逻辑路径，远端使用 `candidates/`、`current` 与 `store/v11/{files,tmp}`。将整个 store 链接到 NFS 会同时移动 SQLite WAL 索引；本次仅外置文件与临时内容。安装 HOME、缓存和临时目录跟随远端候选，避免新增大体积本地缓存。

### 真实路径与 NFSv4 ACL 一起核验

先读取内核挂载表，再访问远端，核对来源、挂载点及嵌套挂载。路径解析后核对约定目录、专属 `.pnpm`、包与入口边界；bwrap 绑定已解析的快照，不绑定可变 `current`。本机无配置时也拒绝未经声明的外置链接。

mode `0755` 或 `umask 022` 无法排除 NAS 的具名及继承写授权，因此 NFSv4 使用原生 `getfattr` 核对 ACL，有效或继承写权限仅允许 `OWNER@`。迁移时用已安装的 `setfattr` 修正专属目录树，既有包字节、链接和执行位仍按已校验本地副本保留。检查失败时阻塞，不靠临时 chmod 绕过授权边界。

### 指针与本地元数据分别原子替换，用记录恢复一致性

本地 SQLite 操作锁串行执行 update，进程退出自动释放。晋升先保存旧指针和本地清单、锁文件的内容；本地临时文件写入并同步后在同一目录 rename，远端临时链接在 NFS 同一目录 rename 替换 `current`。这样避免跨文件系统 rename，同时不声称两套文件系统组成原子事务。

失败时恢复旧状态；中断后下一次 update 先恢复再观察。恢复记录存在时 `check-current` 阻塞，`observe` 保持元数据观察，两者不持 update 锁。恢复未结束则保留记录并阻止晋升。保留完整候选使恢复只需替换小文件和指针，无需搬回包字节；workspace 配置创建候选时复制，晋升不替换本地固定配置。

### 固定身份与历史保留独立于当前指针

本地清单和锁文件继续定义选中精确版本，候选复核还确认其他选中产品没有被旧候选回滚。来源审计沿受控路径核对版本、integrity 和包内容；远端存储位置不产生新来源身份。完整候选、失败候选及迁移前备份均保留，`current` 仅选择运行环境。既有缺失历史原件的审计状态如实保留。

## Risks / Trade-offs

- NFS 不可用会影响当前二进制及维护 → 挂载失效时报阻塞；知识查询与发布继续使用本地发布数据。
- hard 挂载断连可使文件操作持续等待 → 不将子进程超时等同于文件操作结束或回滚完成，保留现有挂载方式并说明运维限制。
- 本地元数据与远端指针分步更新存在中断窗口 → 使用本地锁和恢复记录，恢复前阻止当前检查与新晋升。
- NAS ACL 继承可能覆盖创建模式 → 核验实际有效及继承 ACL，真实 NFS 集成测试验证隐藏授权被拒绝。
- 历史保留增加 NAS 占用，Btrfs 快照延迟本地回收 → 不自动删除历史或备份，以实际 `df` 差值报告，后续空间复测列入任务。

## Migration Plan

以下流程已执行，验收明细见 ADR 0008 与忽略的 `var/managed-packages/migration-*.json`：

1. 串行暂停受管更新，记录目录、版本、启动与审计基线，确认 NAS 空间、挂载及权限。
2. rsync 复制全部 61 个历史目录、当前完整包集与 store 文件到远端暂存区，保留链接及执行位；校验式 dry-run 的 64 个范围均无差异。随后修正专属树 ACL，复核 owner 写与沙箱读取、执行权限。
3. 在 NFS 内建立最终目录及 `current`，本地原目录进入回退区，再建立四处链接并启用配置。切换失败可恢复原目录和配置；本次首次切换发现 NAS 权限问题后已回退，修正后重新切换并验收。
4. 验证本地 SQLite 完整性、真实 NFS 候选晋升与来源审计、沙箱启动、失败及中断恢复。本机相关集成测试 49 项通过；25 个入口启动成功、26 项来源审计通过，既有未选中及阻塞结果与基线相同。
5. 验收通过后仅清理本次已核对的本地副本，释放操作锁并记录 `df`。本次没有净释放，仍有 14 份迁移前 Btrfs 快照，很可能引用旧包字节；未逐份读取其内容，不能量化每份占用。

每天 03:30 的备份在 root/home 冷备成功后保留最新 14 份快照。若持续每日成功，最后一份迁移前快照预计在 2026-10-15 轮换；随后需复测 `df` 才能完成空间验收。此前不宣称已释放约 129.3 GB。
