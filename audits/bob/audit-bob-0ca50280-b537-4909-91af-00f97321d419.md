## 给维护者的结论

28 个官方文档来源全部报了 changed，但其中 23 页并没有读者可见的内容变化。bob.ibm.com 的文档页把部署标识 `BUILD_ID` 内嵌在 HTML 里，同一 URL 重复抓取会得到不同 sha256，差异只在 BUILD_ID 那一处（`server-transports` 页两次抓取全文只差 16 个字符），正文逐字相同。因此本轮没有按 hash 判断变化，而是把每条已发布引用的摘录逐行回到新抓取的页面里比对：23 页全部命中，5 页有实质改动。

实质改动集中在 MCP 与 Skills 两块。MCP 侧最大的变化是**独立 HTTP+SSE 传输被移除**：`url` 键不再被识别，远程 server 只能用 `httpURL`（Streamable HTTP），传输页的对比表也从三列变成 STDIO 与 Streamable HTTP 两列。Skills 侧 `name` 字段从“界面显示名”变成“必须与文件夹同名”，并新增文件夹命名规则（小写 kebab-case、最长 64 字符、非法目录直接跳过），`description` 省略时改为回退到正文第一行而不是忽略该 Skill。这两条都推翻了已发布的配置步骤，因此 `mcp` 与 `skills` 升到新版本；`configuration` 因 MCP 全局路径与 `tasks.retentionDays` 语义改动同步升版，`native_plugins` 只是扩展面对照表里那一行路径跟着改。`custom_agents`、`custom_providers`、`hooks` 三个主题复查后无变化，保留旧版本。

还有一件需要维护者知道的事：**bob 官方文档的字节身份不可用作变更信号**，只要站点重新部署，全部 28 个来源就会在下一轮再次报 changed。要让巡检有意义，bob 的文档来源需要改用抽取正文后的稳定身份（例如 `extracted_sha256` 指向去标签正文，或登记一个 markdown 端点），否则每一轮都要重做一次逐行比对。这是流程建议，本轮没有改扫描器。

## 变化的意义与证据边界

### 独立 HTTP+SSE 传输被移除，`url` 键失效

MCP 页新增 “SSE transport (removed)” 一节，写明 “The url property is not recognised”，只使用旧 HTTP+SSE 传输（MCP 规范 2024-11-05，带独立 `/events` 与 `/message` 端点）的 server 无法连接 Bob；Streamable HTTP 连接内部作为响应通道的 SSE 仍然支持。传输页给出同一结论并补了迁移路径：远程 server 改为单一 POST 端点的 Streamable HTTP，本机 server 改为 Stdio。对应引用 `ref-bob-mcp-sse-removed`、`ref-bob-mcp-transports-removed`、`ref-bob-mcp-props-transport`，均绑定 2026-10-03 快照。

同一批改动还补上了此前缺失的协议版本表：支持 2025-11-25、2025-06-18、2025-03-26、2024-11-05、2024-10-07，连接时协商共同支持的最高版本，2026-07-28 尚不支持（`ref-bob-mcp-versions`）。changelog 2.0.0 里 “bob mcp add … 支持 stdio、SSE、HTTP” 现在只能按 2.0.0 的历史事实读，章节里保留了这一版本边界。

证据只到来源级：Bob Shell 闭源，文档没有给出传输协商失败时的日志字段、重试与退避行为，`mcp.lifecycle` 与 `mcp.diagnostics` 仍是 partial。

### MCP 全局配置路径与 `url` 键在两页之间互相矛盾

MCP 页把全局配置写成 `~/.bob/settings/mcp.json`，OAuth 页仍写 `~/.bob/mcp_settings.json`；OAuth 页的最小示例还在用 `url` 指定远程端点，而 MCP 页已声明该键不再被识别。两处分歧可以用 changelog 2.0.0 的 “Settings are now stored at ~/.bob/settings/settings.json” 解释：MCP 页跟随了新目录布局，OAuth 页停留在 2.0.0 之前（同一页的 `url` 示例也没跟上 SSE 移除）。因此 `mcp.entry` 与 `mcp.definition` 记为 `conflict`，正文用表格并列两方说法与定位，并写明不要把任一路径当成唯一事实、以 `bob mcp list` 的实际读取为准。这条判断是本轮 Agent 的边界推断，不是官方结论。

### OAuth 页重写：身份提供方注册与新的排障清单

OAuth 页现在把可选参数收进 `oauth` 对象（`enabled`、`clientId`、`clientSecret`、`scope`），并新增 “Register Bob with your identity provider” 一节：应用类型 Public / Native / Loopback（Authorization Code with PKCE）、回调 `http://127.0.0.1:33418/callback`、端口被占用时追加 33419–33427、grant types 为 authorization_code 与 refresh_token（`ref-bob-mcp-oauth-props-object`、`ref-bob-mcp-oauth-idp`）。静态 `Authorization` 头的互斥规则表述更明确：加了头就不发起 OAuth 流程，OAuth 生效时 Bob 会移除静态头。排障清单新增“检查配置里是否有静态 Authorization 头”“浏览器或防火墙是否拦截 `127.0.0.1` 回环连接”“redirect URI 不匹配”三条（`ref-bob-mcp-oauth-troubleshoot-steps`）。

### Skills 的 `name` 绑定文件夹名，`description` 可省略

Skills 页现在写 `name` 必须与所在文件夹同名，文件夹名必须是小写 kebab-case（字母、数字、单个连字符）、最长 64 字符，名字非法的文件夹会被跳过；`description` 省略时 Bob 改用正文第一行，而不是忽略该 Skill（`ref-bob-skills-fields`）。这两条改变了 `skills.format` 的字段语义，也给 `skills.discovery` 增加了一条可确认的过滤规则，`skills.conditions` 的失败信号里补上了“先查目录名”。changelog 2.0.3 已记录“目录名非法时给出告警”，与新的跳过规则互为佐证。

### 配置：任务保留只清理未固定的任务

Configuring 页把 `tasks.retentionDays` 改写为“超过该天数后自动删除未固定的任务，已固定的任务永不自动删除”，并保留 2.0.1 的版本警告（`ref-bob-config-retention-pinned`）。其余 schema 键未变。
