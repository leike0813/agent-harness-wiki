# pi 上游巡检报告（2026-10-03）

固定来源 commit `781152fc`（Release v0.73.1，2026-05-07）→ `83692682`（2026-10-03）。npm 来源 `@mariozechner/pi-coding-agent@0.73.1` 未变。

## 这一轮发生了什么

`source-pi-repo` 的 `changed_paths` 不可用作候选清单：受管工作区对两个 commit 都是 shallow 边界，本地没有共同祖先，`git diff` 只能给出两棵树的整体差异（1885 个文件）。改为按固定问题涉及的证据文件逐个复查，14 个被既有引用引用的文件在新提交下全部有变化。七个主题全部受影响，因此全部生成 v3 章节。

## 结论被上游推翻

- **MCP 已是内置能力。** v2 记的“核心不做 MCP、要靠扩展自建”不再成立：现在有 `docs/mcp.md`、用户级与项目级 `mcp.json`、`pi mcp` 子命令、`builtin:mcp` 内置扩展、四种 `exposure`、OAuth 凭据存储、MCP 资源工具，以及扩展侧的 `pi.registerMcpServer()`。新快照 8369268。
- **项目信任机制已存在。** v2 记的“核心没有项目信任提示、也没有允许/拒绝清单”不再成立：`docs/security.md` 定义了受保护资源清单，`settings.md` 有 `defaultProjectTrust`。要点是它不是完整启动边界——项目的 `sessionDir` 在信任判定之前就被读取，且上下文文件不受信任阻断。
- **Skill 名称不再要求与父目录同名。** `skills.ts` 的 `validateName()` 不再接收父目录名，也不再就此告警；文档明确说“既不要求也不告警”。

## 顺序与写法更正

- provider 凭据解析顺序变为 `--api-key` → `auth.json` → `models.json` 的 `apiKey` → 环境变量；v2 把环境变量排在 `models.json` 之前。
- `enableSkillCommands` 只影响交互式命令发现，手动输入的 `/skill:name` 仍然可用；v2 写成“关闭命令注册”。
- 扩展与 provider 扩展的类型导入包名改为 `@earendil-works/pi-coding-agent` / `@earendil-works/pi-ai`。
- 可选内置工具从四个扩到八个（新增 `powershell`、`grep`、`find`、`ls`），默认选择仍是 `read`、`bash`、`edit`、`write`。
- 已知 API 清单新增 `pi-messages`，且该清单现在在 `packages/ai/src/types.ts` 的 `KnownApi` 类型里，而不在 provider 文档中。

## 需要维护者处理（超出本轮写入范围）

- **仓库地址漂移**：上游已迁移到 `github.com/earendil-works/pi`，`registry/sources/source-pi-repo.yaml` 仍登记 `github.com/badlogic/pi-mono.git`，该地址已 301 到新地址，属同仓改名。本轮新引用的 `official_url` 统一使用改名后的 `earendil-works/pi` 地址，内容仍取自同一固定提交 `83692682`，结论适用性不受影响；`registry/` 下的登记文件不在本轮写入范围，留给维护者更新。
- **包作用域迁移**：npm 作用域由 `@mariozechner` 变为 `@earendil-works`，而 `source-pi-npm` 观察到的仍是旧包 0.73.1。两者对应关系本固定来源未说明，未据此改动任何版本结论。
- **章节提升**：本轮子代理没有修改 `registry/chapter-current.yaml`；父进程在聚合阶段依据本轮交付，把 pi 的七个主题全部选为 v3。这不与 harness-maintenance 第 5 节“复核未完成应保留旧版”冲突：本轮独立复核已完成，结论为 `PARTIAL`——七章结论可支撑，四处必须修正已在本轮修正子代理的改动中落实，因此允许提升 v3 为当前版。复核提出的 17 项未完成问题仍按 `partial` 记录，不因此改判。
