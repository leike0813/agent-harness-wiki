## 二、`--tools` 与配置来源语义

CHANGELOG `[Unreleased]` 与 `src/cli/args.ts`、`src/core/settings-manager.ts`、`docs/settings.md` 给出三处实质变化。

**`--tools` 多出第三种形态。** 纯名称 allowlist 是整体替换；只含 `+name`／`-name` 时改的是已解析出的默认选择（`--tools +codemode` 在默认四个之外加一个）。`getToolListError` 判定两条互斥规则：纯名称不能与 `+name`／`-name` 混写；`+name`／`-name` 不接受 `*` 通配。

**`/reload` 与 `--tools` 的关系改写。** v3 写的"`--tools`、`--no-tools`、`--no-builtin-tools` 覆盖 `defaultTools`"只对纯名称一支成立；增减条目在 `/reload` 时作用于重载后的设置，所以用 `-name` 关掉的工具不会因 reload 又回来。CLI 帮助文本同一句写明"Only +name/-name entries add to or remove from the defaults"。

**独立二进制多一组 dotenv 来源。** 从启动目录加载 `.env`、`.env.local`、`.env.development`。构建侧的反向改动在 `scripts/build-binaries.sh`：编译时关掉 bun 的 cwd dotenv 自动加载，注释写明理由是避免项目环境文件泄漏进 Pi 的环境，并引用同一个 issue（#10473）。两条证据合起来确定"哪个目录、哪三个文件"；没有确定的是三者之间的优先级、与进程既有环境变量的覆盖关系，以及 npm 安装的 CLI 是否同样加载。`docs/environment-variables.md` 只区分进程标记、shell 工具会话环境与 provider 凭据三类用途，未记载 dotenv 文件。`config.sources` 因此由 `answered` 改为 `partial`。

**`pi update` 保留策略收紧。** 受管安装不再保留全部旧版本，只保留新版本与被升级的那一版。实现是 `pruneManagedReleases`：激活新版本后遍历 `releases/`，跳过激活版本、当前运行版本与不匹配版本号正则的目录，其余递归删除；删除失败被吞掉，注释写明文件可能仍被占用（Windows 上已加载的原生模块），下次更新再试。这条只覆盖受管安装路径，固定来源没有说明 npm 安装或 Nix 安装是否有对应清理。

以上四条都出自该提交的 `[Unreleased]` 段与源码，属发布前状态。该提交上最后一个已发布版本是 1.0.4。

## 三、`--tools` 与 `mcp__` 前缀工具的关系

v3 记了 server 级 `exposure` 的四种取值，没有记命令行那一层。CLI 帮助文本写明：`--tools` 虽是纯名称 allowlist（可带 `*` 通配），但默认保留 MCP 工具，除非有条目以 `mcp__` 开头；官方示例用 `pi --tools read,bash,codemode,'mcp__radius__*'` 把范围收到一个 server。

值得单独说明的是三层之间的关系：server 级 `exposure` 决定工具怎么到达模型，`--tools` 决定哪些工具被启用，而本轮新增的 `+name`／`-name` 形态不带任何 `mcp__` 条目，因此也触发不了那条保留规则——`mcp__` 只对纯名称 allowlist 有意义。

版本边界要写清：`mcp__` 保留规则在上一固定提交 `28dcce2` 已经存在（对比 diff 中它是上下文行，不是新增行），本轮新增的是 `+name`／`-name` 形态。缺口是 `mcp__` 条目与 `exposure`、`toolExposure` 三者的叠加顺序，固定来源没有给出说明。
