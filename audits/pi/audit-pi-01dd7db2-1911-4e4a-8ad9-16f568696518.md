## 变化的意义与证据边界

### settings.json 的 `$schema` 发布地址与资源过滤的 `~` 展开（configuration）

四处一致：`docs/settings.md` 第 5 行、`schemas/settings.schema.json` 第 3 行、`schemas/models.schema.json` 第 3 行、`scripts/generate-schemas.ts` 的 `schemaBaseUrl` 常量都指向 `https://pi.dev/schemas`；生成器侧 `SchemaArtifact` 的 `path` 字段拆成 `filename`，输出路径改由渲染阶段拼 `schemas/<文件名>`。这把 v5 里「`$id` 指向仓库 raw URL」的结论推翻，configuration v6 改写为新地址并补入文档给出的推荐写法。

`src/core/package-manager.ts` 的 `matchesAnyPattern` 与 `normalizeExactPattern` 改为先调 `normalizePath()`，默认展开 `~`，因此 `!~/skills/pdf` 这类条目从「匹配不到」变为按实际路径匹配。`CHANGELOG` 第 37 行把这次修复写成 `extensions`、`skills`、`prompts`、`themes` 四个设置数组的问题。

跨主题扩展的依据是「章节陈述了该键」：同一套 `applyPatterns` 服务包清单与设置数组，所以 native_plugins 的 `plugins-api` 同步更新；`models.json` 的示例与 `models.schema.json` 的 `$id` 属于 custom_providers 的 `providers-models`，同步更新。skills 的 `skills-extension-fields` 陈述同一组键，但不在本轮指定章节范围，未改章节、只在审计中记录。

未变：键集合、默认值、合并逻辑、读取路径在 7bd01fb9 上都未被改动，`config.defaults`／`overrides`／`runtime`／`trust`／`migration` 的结论不扩展。

### OpenRouter 的按 key 模型清单（custom_providers）

`docs/providers.md` 新增一整节：`/login openrouter` 或 `OPENROUTER_API_KEY` 认证后只列该 key 可用的 chat 模型及其 context size、最大输出与价格，来源是 OpenRouter 的 `/models/user`；区域端点通过 `models.json` 的 `baseUrl` 生效；端点返回 401/403/404 时回落全量清单。刷新时机是交互模式启动、`/model` 打开、`/login` 之后与 `pi update --models`，最后清单保存后离线、`pi -p` 与 RPC 均用保存值。实现侧由 `packages/ai/src/providers/openrouter.ts` 的 `personalizeOpenRouterCatalog` 与 `remote-catalog-provider.ts` 的 `withPersonalizedCatalog` 支撑。

这条只补 `providers.models`；`providers.metadata`／`forwarding`／`responses`／`diagnostics` 本轮无新证据，仍按 partial 保留。

### `reachesTools`、命名空间 `aliases` 与资源列举时机（mcp）

工具定义新增 `reachesTools(input)`，MCP 扩展据此判断同名替换工具能否为 MCP 工具激活，并在 `tool_call` 时只等待该调用可能触达的 server；命名空间新增 `aliases`，MCP 命名空间用 server 名。连接时不再列举资源（列举大挂载盘可能很慢），`pi mcp list` 改为打印 `offers resources`，JSON 的 `resources` 从计数变布尔。另有三处：`McpTransport.send()` 新增可选 `signal`（修掉授权刷新后重试已取消请求）、`CallToolResult.structuredContent` 放宽为 `unknown`（MCP 2026-07-28）、`pi mcp login --timeout` 语义改为整个登录流程的时间上限。

`mcp.diagnostics` 仍缺「配置被读取／server 已连接／工具可见／调用成功」四层分离的诊断命令，保持 partial。

### 实验运行时移除与摘要不再含 thinking（local_transcripts）

`src/experimental/session-catalog.ts` 与 `src/experimental/durable/sessions.ts` 不再出现在源码树里，`CHANGELOG` 的 Removed 段记录未发布的实验 server／client／plugin 栈连同其源码导出一起移除，`package.json` 的 `files` 不再排除 `dist/experimental` 与 `dist/cli/experimental`。`transcripts-database-and-index` 原本正以这两个文件加该排除项为证据，因此新建 v2，保留「不发布」这一条件判断，并明确边界：移除的是那一组栈而非整个 `src/experimental` 目录（`source-resolver.ts` 在 7bd01fb9 仍存在且仍被 `generate:schemas` 引用），两个文件的形态按 28dcce2 记录。

`serializeConversation()` 改为跳过 thinking 块（压缩、分支摘要与 bug 报告共用）。这只改摘要输入，thinking 仍照常写入 `.jsonl`，v2 明确区分二者，未改动 `transcripts.schema` 的记录形态结论。
