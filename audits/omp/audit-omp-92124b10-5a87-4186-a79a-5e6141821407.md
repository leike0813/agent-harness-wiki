# OMP 上游审阅报告 · 2026-10-04

## 给维护者的结论

OMP 在本轮跨了一次很大的上游变更：仓库修订从 `dff728c` 走到 `69e8c9e`，虽然只隔一个提交，却动了 3127 个文件（697 新增、70 删除、2346 修改、258867 行新增）。这不是一次局部修补，而是一次包含大规模结构调整的发布。

七个主题全部出现读者可见的机制变化，因此本次为 omp 发布了 `v3` 章节，旧的 `v2` 文件全部保留在仓库里。值得优先知道的三件事：

第一，Skill 同名冲突的处理方式变了。原来同名技能按优先级先到先得、后来者被挤掉；现在正文不同的同名技能里高优先级者保留裸名，其余变体被加上 `命名空间/名称` 后缀并保留下来，被挤掉的 provider 技能仍然可达。这不是措辞变化，是用户配置同名技能后行为会变的类型。

第二，设置层的合并规则出现了一条反直觉规则。settings capability 的项**不**去重，provider 是从高优先级往低优先级访问的，所以低优先级 provider 的项目设置可以覆盖高优先级 provider 的设置。上一版没有这条。

第三，两处状态在独立复核后被改回。`config.migration` 现为 `answered`：`69e8c9e` 的 `docs/config-usage.md` 仍保留 “Migration behavior still active” 一节，写明启动时（且仅当全局 `config.yml` 与 `config.yaml` 都不存在）从 `settings.json` 迁移、与 `agent.db` 合并后写入 `config.yml`，并附两条字段级改名。`hooks.events` 现为 `answered`：`docs/hooks.md` 的 “Event surfaces” 一节按 session、agent/context、tool 三组枚举了第一方事件全集。复核还纠正了一处归因错误：迁移步骤本来就在 `config-usage.md` 里，v2 引用 `ref-omp-settings-migration-doc` 的 `official_url` 指向的也是该文件，不存在一个承载迁移步骤的 `docs/settings.md`。

风险提示：npm 包从 18.3.4 升到 18.5.1，但按契约没有据此制造任何章节变化，也没有建立任何源码到包的版本映射——本轮所有新章节都固定在仓库修订 `69e8c9e` 的文档上，没有把任何 runtime 版本标为已验证。

## 变化的意义与证据边界

### Skill 同名冲突改为命名空间保留（skills.collision）

变化来自 `69e8c9e` 的 `docs/skills.md`“Collision and duplicate handling”与同名小节：capability 层仍按名去重供 `items` 视图使用，`loadSkills()` 则从去重前的超集工作；正文与 frontmatter 深度相等的同名技能被静默丢弃，正文不同的则给其余变体加命名空间后缀。裸名归属顺序是作者技能压过 registry 包（新增的 `skillshare` provider）、自定义目录技能压过 provider 技能、其余先到先得。

影响 `skills.collision`，并通过命名空间解析（`skill://` 与 `/skill:` 记号）与来源过滤（`skills.conditions`）外溢到其它问题。证据能证明文档声明的行为；本轮没有在隔离 HOME 下实际放置技能观察告警，所以“哪些警告出现在哪个时机”仍未取证。来源引用：`ref-omp-skills-collision-doc-69e8`、`ref-omp-skills-namespaced-doc-69e8`、`ref-omp-skills-providers-doc-69e8`。

### 设置层不去重，低优先级 provider 可覆盖高优先级（config.overrides）

`docs/config-usage.md` 的“8) Precedence rules to rely on”明确 settings capability 项不去重，`Settings.#loadProjectSettings()` 按返回顺序深合并，而 provider 按高到低优先级访问。影响 `config.overrides` 与 `config.sources`。同一文件还把层序写成六级具名序列，并区分 `PI_CONFIG_DIR`（通用 helper 的用户根）与 `PI_CODING_AGENT_DIR`（仅默认 profile 的 agent 目录消费者，命名 profile 忽略它）。来源引用：`ref-omp-config-layers-doc-69e8`、`ref-omp-config-precedence-doc-69e8`、`ref-omp-config-roots-doc-69e8`。

### 技能来源新增两个 provider（skills.roots）

`skillshare` 优先级 95（`omp skill install` 锁定的包）、`agent-plugins` 优先级 75（可移植包）。文档同时声明作者技能在同名时压过 `skillshare`，构成一条独立于纯数字排序的覆盖规则。影响 `skills.roots`、`skills.collision`。来源引用：`ref-omp-skills-providers-doc-69e8`。

### Claude 市场插件 agent 的用户作用域门控（agents.entry）

跨 harness 的裸目录在本版仍然被有意跳过——`.claude/agents`、`.codex/agents`、`.gemini/agents` 的 frontmatter schema 不是 OMP 的 task-agent 契约，原生配置目录列表由 `TASK_AGENT_CONFIG_SOURCE = ".omp"` 过滤。这一条上一版就已记录，本版未变，需要更正的是把「市场插件 agent 被纳入」当成本轮改判的说法：上一版已经把 Claude 市场插件的 `agents/` 列为发现来源。真正由本版确立的是这条路径上的门控：需要 `isProviderEnabled("claude-plugins")`，用户作用域根还要额外满足 `isUserSourceEnabled`，`origin: "omp"` 的自有安装与 `--plugin-dir` 根豁免。同一节还记录扩展包的 `extensions:` 数组由拼接改为整数组替换。影响 `agents.entry`。来源引用：`ref-omp-agents-cross-harness-skip-doc-69e8`、`ref-omp-agents-plugin-gating-doc-69e8`、`ref-omp-agents-discovery-doc-69e8`。

### 凭据顺序新增“扩展配置回退”一档，`auth: oauth` 免除 apiKey（providers.auth）

`docs/providers.md` 的凭据顺序在登录 key 与环境变量之间新增第 5 档：同时注册 `apiKey` 引用与 OAuth/login 流程的扩展 provider，该引用排在已存 OAuth 与登录 key 之下。`docs/models.md` 的“Allowed auth/discovery values”则明确 `none` 与 `oauth` 都免除自定义 provider 的 `apiKey` 要求，而 `oauth` 不创建凭据也不注册登录流程。影响 `providers.auth`、`providers.protocol`。来源引用：`ref-omp-providers-credentials-doc-69e8`、`ref-omp-providers-auth-values-doc-69e8`。

### 扩展加载改为并发导入、串行绑定，并新增精确模块白名单（plugins.model / plugins.discovery / plugins.lifecycle）

`docs/extensions.md` 与 `docs/extension-loading.md` 记录模块并发导入后按路径顺序串行绑定工厂、工厂可重绑到新会话而不解算模块图；`--trusted-extension 绝对路径` 只加载列出的文件、绕过发现、不能与 `-e`/`--hook` 组合、白名单模块加载失败会中止启动。影响 `plugins.model`、`plugins.discovery`、`plugins.lifecycle`、`plugins.diagnostics`。来源引用：`ref-omp-extensions-load-doc-69e8`、`ref-omp-extension-loading-order-doc-69e8`、`ref-omp-extension-loading-allowlist-doc-69e8`。
