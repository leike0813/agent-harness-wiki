## 给维护者的结论

`@oh-my-pi/pi-coding-agent@18.3.4` 的精确 npm 包包含可读 TypeScript 源码，这让本轮能够沿实际发现函数追到用户 agent 目录。已接受的窄结论是：OMP 原生用户 agent 定义可从 `~/.omp/agent/agents/*.md` 被发现。它有包内目录声明和发现调用两处 Evidence。

## 变化的意义与证据边界

### Agent 路径草案有可追的代码链

包内 `src/task/discovery.ts` 第 5 行列出 OMP 用户 agent 目录，约 91–109 行调用 `getConfigDirs("agents", { project: false })` 并把用户目录纳入发现根。两处[固定 Evidence](../../knowledge/omp/evidence/evidence-omp-user-agents-path.yaml)和[发现调用 Evidence](../../knowledge/omp/evidence/evidence-omp-user-agents-discovery.yaml)指向同一个 `18.3.4` 包的 Snapshot，依据均为 `source_inspected`。这支持已接受的[路径 Claim](../../knowledge/omp/claims/claim-omp-user-agents-path.yaml)，`availability: supported`、`delivery: native`、无附加条件；它不支持“已加载一个 agent”或“agent 可成功执行”。

### 代码入口不等于机制整体可用

`src/mcp/` 有 manager/types，`src/extensibility/hooks/` 有 loader/runner，`src/commands/plugin.ts` 暴露 install、list、enable、doctor 等命令，设置代码记录分层来源。这些源文件都属于精确包，调查价值高于未标版本的网页；但要发布具体运行结论，还需追查启动条件、配置值、信任状态和执行结果。尤其 plugin 命令存在，不能推断任意插件已经 `loaded/active/healthy`；`settings.ts` 的层级也不能一次性证明每个键的覆盖规则。
