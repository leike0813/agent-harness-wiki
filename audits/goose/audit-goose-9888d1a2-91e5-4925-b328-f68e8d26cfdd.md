## 变化的意义与证据边界

### 首次运行的 goose mode 询问（configuration）

影响 `config.defaults`、`config.runtime`、`config.diagnostics`。`handle_first_time_setup` 在 provider 配置分支之后追加一步，仅当 `get_goose_mode()` 返回 `NotFound` 才执行；`get_goose_mode_strict` 的实现确认了取值顺序是环境变量 → 合并后的配置文件 → `NotFound`，因此设了 `GOOSE_MODE` 的用户不会被问。三个单元测试把这条顺序固定下来：环境变量已设时不弹界面且不创建 `config.yaml`，配置里已有值时保持原值。

证据能证明「何时问」「问什么」「结果写到哪」，不能证明任何具体已发布版本的交互文案。

### 三个旧缺口闭合（configuration）

* **功能开关**：机制就是配置键 `experiments`（名字到布尔的映射），权威清单是常量 `ALL_EXPERIMENTS`，读取前与清单对齐——补入清单里的名字、移除不在清单里的名字。该常量当前是空数组，所以现阶段没有激活的实验，用户手写的实验名会在读取时被清掉。v1 记的「feature flag 机制未确立」到此改为已确立且当前为空。
* **诊断输出**：`goose info` 固定打印版本与四个路径（`Config dir`/`Config yaml`/`Sessions DB (sqlite)`/`Logs dir`），路径缺失时向上找第一个存在的父目录并区分可创建、只读父目录、无法检查、无可写父目录。`-v` 打印 `all_values()` 的合并结果；**这条边界值得记住**——`all_values()` 取合并后的配置文件再加解析后的 `GOOSE_PROVIDER`/`GOOSE_MODEL`，不把任意环境变量灌进清单，所以环境变量覆盖不会在 `-v` 里显式出现。`--check` 真的发一条 `Say 'ok'` 补全并计时，失败按未配置／模型无效／provider 构造失败／provider 请求失败四类分标签（源码注释明确说不要把 provider 构造问题误标成 `Auth: FAILED`），失败时返回错误可供 CI 前置验证。`goose doctor` 不打印配置，而是建不落库的交互会话执行 `/doctor`。
* **`GOOSE_MODE` 默认值**：用 `config_value!` 两参数形式声明，**没有键级默认值**；实际默认来自 `GooseMode` 枚举 `Auto` 变体的 `#[default]` 与调用点的 `unwrap_or_default()`。这与文档默认值表一致，v1 的「无法在源码侧核对」不再是缺口。

### 平台扩展键也走配置链（configuration）

`tom.rs` 把 `GOOSE_MOIM_MESSAGE_TEXT`/`GOOSE_MOIM_MESSAGE_FILE` 从裸 `std::env::var` 换成 `Config::global().get_param`，这两个键因此可以写进 `config.yaml`。这是单个扩展的键解析改动，不构成跨主题关键加载机制变化。

### 判定为无读者可见变化的部分

* **custom_providers**：`githubcopilot.rs` 新增 401/403 令牌失效与单次重试、鉴权错误不再重试；`bedrock.rs` 把 cache 读写计入 `input_tokens` 并保留上游 `total_tokens`；`openai.rs` 为 `gpt-6.1-sol` 增加必须启用 reasoning 的映射；`canonical_models.json`／`provider_metadata.json` 刷新 `model_count`。这些都在内置 provider 与 provider-types 侧，已发布的「自定义 provider 路径内没有重试/退避/错误映射代码」未被推翻。`openai.rs` 的模型名启发式属请求整形细节，仍在本章声明的未签出范围之外，不据此制造新结论。
* **skills / hooks / mcp / native_plugins**：changed_paths 未包含这些主题的机制文件，四章引用未受影响。
* **界面边界**：catalog 为 goose 声明了 `cli` 与 `desktop` 两个界面，但七章只有 `cli` 的答案，`desktop` 由查询派生为 `not_investigated`。`goose-permissions.md` 本轮的改动只涉及 Desktop 标签页（权限模式改为 Settings 里的 `Default Mode`，每个会话保留自己的模式），`acp/*` 与 `ui/desktop/*` 同属 desktop 界面，未写入任何章节，也未据此给 desktop 补答案。
* **不属七类主题**：`goose session export` 新增 `--format html`、移除 `--nostr`/`--relay`，`goose session import` 不再接受 Nostr 分享链接。没有固定问题覆盖会话导出/分享。
