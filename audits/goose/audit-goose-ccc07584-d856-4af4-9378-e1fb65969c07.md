`crates/goose/src/config/base.rs` 的 diff 只有 45 行新增：新增 `Config::resolve_goose_mode` 与它的两个单元测试，没有新增或删除任何 `config_value!` 键，`merge` / `sources_order` / `set_param` / `secret` / `migrations` 全部未变。

新入口包在既有 `get_goose_mode_strict` 外面，**只把 `ConfigError::NotFound` 换成 `GooseMode::Auto`，其余错误原样上抛**：

```rust
pub(crate) fn resolve_goose_mode(&self) -> Result<GooseMode, ConfigError> {
    match self.get_goose_mode_strict() {
        Ok(mode) => Ok(mode),
        Err(ConfigError::NotFound(_)) => Ok(GooseMode::Auto),
        Err(error) => Err(error),
    }
}
```

同轮 `claude_code.rs`（映射成 `ProviderError::RequestFailed`）与 `amp_acp.rs` / `claude_acp.rs` / `copilot_acp.rs` / `pi_acp.rs` / `codex_acp.rs` 全部由 `get_goose_mode().unwrap_or(GooseMode::Auto)` 改为该入口，`codex_acp.rs` 内部原有的等价私有函数被删除。

用户可见的后果：`GOOSE_MODE` 缺失仍是 Auto（已发布结论不变），但**值写错**（`GOOSE_MODE=invalid` 或配置文件里的非法值）在这批 provider 上从「静默按 Auto 启动」变成「构造失败」。仓库自带单元测试逐条固定了这一区分，因此 `config.runtime`、`config.defaults`、`config.diagnostics` 改写。

未延长到 `config.sources` / `config.overrides` / `config.trust` / `config.migration`：键加载器、合并顺序、优先级层、密钥链与迁移规则逐行未变。`config.runtime` 与 `config.diagnostics` 仍为 `partial`（未逐键核对源码环境变量清单；`goose doctor` 检查项未追进会话层）。
