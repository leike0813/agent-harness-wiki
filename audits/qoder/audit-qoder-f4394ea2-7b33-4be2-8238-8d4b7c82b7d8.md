## 变化的意义与证据边界

### skills.roots：当前原件仍支持两个发现根与冲突规则

受影响问题 `skills.roots`（章节 `qoder-qoder-skills-v3`，小节 `skills-roots`，surface `qoder`，状态 `partial`）。实际读取 `archive/qoder/artifact-source-qoder-docs-cli-skills-cdeddfdedca4/source.md` 的 `Where Skills live` 与 `Choose Storage Location` 两节：两处都仍是用户级 `~/.qoder/skills/{skill-name}/SKILL.md`（scope: All projects for current user）与项目级 `.qoder/skills/{skill-name}/SKILL.md`（scope: Current project only）两行表格，没有新增第三个根目录；冲突行仍是 `When names conflict, user-level Skills override project-level Skills.` 与 Tip 段的同一句。

章节里"用户级根随 `QODER_CONFIG_DIR` 整体移动"那条仍是跨页推断（引用 `ref-qoder-cli-configdir`，来自 `cli/config-scope.md`，本轮 unchanged），Skills 页本身没有写这条规则——推断边界不变。

已发布的缺口"没有扫描深度、是否跟随符号链接、目录大小上限、`.gitignore`/`.qoderignore` 是否影响扫描"在当前页仍然成立：全文检索无相关表述。**记录为缺口，不作为已确认事实。**

### skills.format：frontmatter 字段与约束未变

受影响问题 `skills.format`（小节 `skills-format`，状态 `answered`）。`Organize Directory Structure` 一节的目录树（`SKILL.md` 必需，`REFERENCE.md`、`EXAMPLES.md`、`scripts/`、`templates/` 可选）与 progressive disclosure 示例逐字一致；`Write SKILL.md` 一节的 frontmatter 示例与字段表仍只有 `name`（必需，小写字母/数字/连字符，最长 64 字符）与 `description`（必需，最长 1024 字符）两行，没有新增或移除字段。

### config.sources / config.defaults / config.migration：不由本轮变化来源背书

这三道问题的 `source_refs` 全部落在 `extensions/hooks.md`、`user-guide/rules.md`、`user-guide/indexing.md`、`user-guide/commands.md`、`cli/settings.md`、`cli/config-scope.md`——本轮这些来源 observed 与 baseline 逐字相同。变化来源 `docs/cli/settings-reference` 只被 `config.runtime` 引用，不在本任务范围内。

对 `docs/cli/settings-reference` 当前原件做了全文通读以确认它没有推翻章节结论：键表、`default` 与 `Restart` 列、三层 `settings.json` 路径表、`Environment Variables` 两节都与已发布内容一致；全文没有任何弃用、重命名或迁移段，因此 `config.migration` 那条"未记录配置键迁移/弃用/版本兼容规则"的缺口在当前页仍然成立——按缺口记录，不确认该页已明确否认。

### ide-tools 页：本轮范围内不相关

`archive/qoder/artifact-source-qoder-docs-ide-tools-b1f0804fa72d/source.md` 全文只有 Search / Edit / Execute commands / Find problems / Update memories / Diff view / Image generation / Message queue，无 `skills` 或 `settings.json` 内容。该页只背书 `agents.roles`，超出本任务范围，仍 pending。
