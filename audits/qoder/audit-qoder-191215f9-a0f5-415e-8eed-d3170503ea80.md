## 变化的意义与证据边界

### CLI 清理语义被改写（`transcripts.cleanup`、`transcripts.scope`）

新页面的 `general (General)` 表与表后一段给出（`snapshot-qoder-docs-cli-settings-reference-7591206ca400`）：

- `general.sessionRetention.enabled` 默认 `false`，"Disabled by default; explicitly set to `true` to enable."；
- `general.sessionRetention.maxAge` 默认 `30d`，语义为"启用后删除超过该时长未修改的会话"；
- `general.sessionRetention.minRetention` 默认 `1d`（保留期下限）；
- `Sessions and tool outputs in tool-outputs/ are retained by default. Background task .output files continue to be cleaned independently after 7 days. Diagnostic logs (logs/runs/ and logs/sessions/) are independently retained for 30 days; logs for the current run and the run referenced by latest are protected from cleanup.`

旧版只写了会话保留三项且默认开启。因此：

- 已发布文本"`general.sessionRetention.enabled` 默认 `true` 控制自动会话清理"被推翻，v2 改为默认关闭并写明显式启用条件。
- `transcripts.cleanup`（cli）由单一机制改写为多机制：会话清理（默认关闭）、`tool-outputs/` 默认保留、后台 `.output` 7 天、诊断日志 30 天且保护当前与 `latest` 运行。仍为 `partial`：三类存储的文件形态与路径、级联、手动删除后果、删除前需要停止的写入者仍无来源。
- `transcripts.scope`（cli）由 `unknown` 升为 `partial`：现在能确认 CLI 把会话、`tool-outputs/` 工具输出、`logs/runs/`+`logs/sessions/` 诊断日志分开存放且保留期独立；但消息与工具事件落在哪类文件、是否有开关控制落盘仍无来源。

### Quest 窗口退役（`transcripts.lifecycle`）

`user-guide/quest/overview.md` 当前页面顶部声明 Quest 窗口已退役：新用户不可用、存量访问分批关闭、窗口随时可能消失，官方建议迁回 Qoder（`snapshot-qoder-docs-ide-quest-ffe9bfbdad48`，`ref-qoder-lt-quest-retired`）。已发布的任务级回滚、Pin/Fork/重命名/删除仍见于同一页面（`ref-qoder-lt-quest-notes`、`ref-qoder-lt-quest-task-ops` 摘录仍逐字命中），故 v2 只补一句退役边界，说明这些操作不能当作长期的分支或归档手段。`transcripts.lifecycle` 保持 `partial`。

- IDE 侧 schema、命名、位置、格式、数据库、读取与排错结论全部沿用：`extensions/hooks.md`、`user-guide/chat/overview.md`、`troubleshooting/troubleshooting-guide.md`、`user-guide/indexing.md`、`cli/config-scope.md` 本轮 observed = baseline，且引用逐字命中。
