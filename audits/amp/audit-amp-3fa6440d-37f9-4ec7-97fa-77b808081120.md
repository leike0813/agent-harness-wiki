## 语义判断

新证据改写的是**已发布的继承与路由语义**，因此按高影响处理：

1. `amp-cli-custom_agents-v2` 的 `agents-format` 表格与 `agents-overrides` 写「省略 `model` 时继承该
   模式的模型与 reasoning effort」。`fbebb8b34b73` 起就存在的原文是：继承内置模式的 agent 是独立
   模式，省略 `model` 时取**插件加载那一刻 Amp 对该内置模式的默认模型与 effort**，你的 Tune Modes
   固定与工作区固定都不改变它。即 v2 **漏覆盖了一个自基线以来就存在的既有歧义**（原文自身在该节
   前一段仍写「inherits the mode's model and reasoning effort when you omit `model`」），不是本轮
   推翻了已发布说法；该歧义到 2026-10-13 新版仍未消除，章节按现状披露而非判定为已解决。
2. `model` 只固定主代理，Oracle 与其他子代理保持自动路由；固定这些角色必须写 `oracle` 与
   `subagents`，两字段独立覆盖，被固定模型不可用时回退自动路由。v2 只写了「字段独立覆盖」，没有
   写清「主代理 pin 不传播」。
3. Raw Models 里选单个模型同样只固定主代理；Tune Modes 只能改内置模式的三个角色，改不了插件
   agent 的路由。v2 未涉及 Raw Models。
4. 三个角色全部固定也**不覆盖** supporting system models（图像生成、线程命名等）。这是新增的边界。
5. 对 `providers.forwarding`（哪些可写参数只影响路由、不映射到后续请求），第 2–4 条正是成文依据：
   主代理层的 `model` / Tune Modes pin / Raw Models 选择只作用于主代理角色，子代理与系统模型各走
   自己的路由。

**已发布但本轮证据未改变、维持原样的答案**：`agents.entry`、`agents.invocation`、`agents.diagnostics`、
`agents.limits`（状态仍为 partial）、`providers.auth`、`providers.models`、`providers.metadata`。
依据是上述对照中相关章节逐字未变（`agents.invocation` 引用的 `ref-amp-dial-off-dial` 所在节的 CLI
段落未变，变的只有 web 选择器段落）。

**文档不保证的**：三页只有 `lastModified: 2026-10-13`，不指向任何 Amp 版本，所以全部结论仍限于来源级
（`version_applicability: unknown`），本轮不写任何软件版本映射；文档写明了「模型不可用→运行期回退到
Amp 路由」（类型参考 `oracle` / `subagents` 注释），但没有写明这些 pin 是否进入 provider 请求本身。
