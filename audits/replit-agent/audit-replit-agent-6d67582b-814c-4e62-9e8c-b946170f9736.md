## 变化的意义与证据边界

### Replit AI Integrations 的改动落在未被引用的区段

变化影响的问题 ID 是 `providers.auth`、`providers.protocol`、`providers.responses`、
`providers.diagnostics`，对应小节 `providers-auth-forwarding` 与 `providers-diagnostics`。
这四条答案各自依赖的三条引用（`ref-replit-prov-aiint-overview`、
`ref-replit-prov-aiint-byok`、`ref-replit-prov-aiint-plan`）逐行在新抓取的原件中原样命中，
被引小节正文未变。改动本身集中在没有被引用覆盖的区段——Grok 与 Jev 条目、OpenRouter 的隐私
与可用性默认值、输出类型说明。

因此 `providers.auth` 维持 `not_applicable`（Agent 推理链路没有用户可填的凭据字段），
`providers.protocol` 维持 `not_applicable`，`providers.responses` 维持 `unknown`
（流式、工具调用、错误与重试仍无登记来源），`providers.diagnostics` 里关于计划可用性的
判断（Starter 禁用、Core 可用、Pro/Enterprise 默认关闭需管理员开启）也维持不变。

仍缺的部分没有变化：上下文窗口、输出上限、工具与视觉等能力元数据，以及参数如何映射到
请求，登记来源依旧没有表达，所以 `providers.forwarding` 继续是 `unknown`。

### 文档索引变化后，"不存在 hook／插件页面"是否仍成立

`hooks.diagnostics` 和 `plugins.diagnostics` 都把官方文档索引当作否定证据：索引里没有任何
hook 页面，因此 hooks 主题全章判 `not_applicable` 并在诊断小节列出替代观察点；同理索引里
没有任何插件页面，plugins 主题判 `not_applicable`。

索引变化后这两条否定结论必须重验。对新抓取的 408 行索引全文复核：`hook`、`plugin`、
`extension` 三个关键词零命中。两条否定结论继续成立，
`replit-agent-web-hooks-v1` 与 `replit-agent-web-native_plugins-v1` 不需要改写。

### 另外四个主题的连带影响没有落到正文

配置、custom_agents、mcp、skills 四个主题的 impacts 只落在各自的 `*-scope` 小节，
引用的仍是上面那两条索引与集成文档，同样复核为未变，因此不新建章节版本。
