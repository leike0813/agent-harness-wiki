# Cline 上游审阅报告 · 2026-10-06

## 给维护者的结论

Cline 的仓库从 `dec80dad` 推进到 `cd80a20e`，本轮唯一影响已发布章节的变化是 Anthropic 直连的 provider 选项规则：`provider.anthropic.direct` 不再对所有 anthropic 端点一律注入服务端拒答回退，改为只在官方端点注入。`{#providers-auth}` 原文把 `baseUrl` 描述成必填的合法 URL，这句话现在少了一半——`baseUrl` 还会决定这个选项是否进入请求体。已新建 `cline-cli-custom_providers-v3` 承载这条条件化事实，v1 与 v2 原样保留。

这不是本轮唯一的判断。`runtime/safety/rules.ts` 与 `extensions/config/user-instruction-service.ts` 的改动把规则筛选与排序收敛到共享函数：过滤条件与 watcher 路径完全一致，但合并规则那条路径**新增了按 name 的 `localeCompare` 排序**，此前只按记录顺序渲染。configuration 与 skills 两章都没有记录 system prompt 里规则段的渲染顺序，所以不改写正文——但这是父进程 triage 结论之外的一个更精确的描述，建议保留在案。

`core/src/index.ts` 确实变了，但只在规则渲染导出块多导出一个符号，对 `native_plugins` 的「插件可导入哪些符号」类答案无影响，已核对并写明。

## 变化的意义与证据边界

### Anthropic 直连的拒答回退变成端点条件

规则 `provider.anthropic.direct`（`phase: "provider"`）的 `applies` 仍只看 `request.providerId === "anthropic"`，命中时仍一律 `suppresses: { genericFanout: true }`；变化只在 `build`：基线版本无条件返回 `{ anthropic: { fallbacks: "default" } }`，现在改为 `isOfficialAnthropicEndpoint(input.context.config.baseUrl)` 为真才返回该补丁，否则返回 `undefined`。官方端点判定在 `url.ts` 的 `isOfficialAnthropicEndpoint`：`baseUrl` 为空视为 provider 默认即官方端点，`new URL(baseUrl).origin === "https://api.anthropic.com"` 为官方，解析失败按自定义处理。

命中 `providers.auth` 与 `{#providers-auth}`：这条路径解释了为什么同一个 provider 换 `baseUrl` 会得到不同的请求体。证据 `ref-cline-provider-anthropic-endpoint` 与 `ref-cline-provider-anthropic-fallback-rule` 新固定到 `cd80a20e`，逐行核对摘录与工作区一致。

边界写清楚了：端点判定刻意放在 `build` 而非 `applies`，所以自定义端点保留 fanout 抑制、只是拿不到只属于 Claude API 的 `fallbacks`；「严格 schema 的代理会以 400 拒绝」是规则注释里的作者自述，章节按意图而非运行观察表述。全部结论只覆盖固定提交的源码树，未绑定任何 npm 发布版本。

### providers.forwarding 已定位但本轮未处理

同一个注入也是「可写参数如何映射到请求」的答案，但 `#providers-forwarding` 现在只写 `ProviderConfig` 的字段流转和「`capabilities` 不变成请求字段」，没有 provider 选项规则这一层。本轮任务范围限定为 `providers.auth`/`entry`/`models`/`responses`，因此只把它留在 `pending_question_ids` 并写明理由，不改正文。

### configuration 与 skills：核对后不改写

`listEnabledRulesFromWatcher` 改为委托 `listEnabledRulesFromRecords`，而 `isRuleEnabled` 就是 `disabled !== true`、`formatRulesForSystemPrompt` 不排序，所以过滤与排序结果不变。`user-instruction-service.ts` 的 `cline-combined-user-instructions:rules` 渲染此前只做 `disabled !== true` 过滤，现在经共享函数后也按 name 排序——渲染顺序由记录顺序变为按名排序。两章都没有记录该顺序，答案不受影响。`ref-cline-skills-ambiguous`（`user-instruction-service.ts` 88-122 行）与 `ref-cline-plugin-alias`（`core/src/index.ts` 30-40 行）在 `dec80dad..cd80a20e` 区间逐字节未变，无定位漂移。

### native_plugins：确认无影响

`core/src/index.ts` 的改动只有一行导出新增 `loadRulesForSystemPromptFromRecords`，位于 `runtime/safety/rules` 的导出块。插件可导入的 manifest/extension 符号与 `plugins.api` 答案不变，`ref-cline-plugin-alias` 引用的是 30-40 行的类型别名块，未受影响。
