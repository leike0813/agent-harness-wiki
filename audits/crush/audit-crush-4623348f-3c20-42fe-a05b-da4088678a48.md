# Crush 上游审阅报告 · 2026-10-03

## 给维护者的结论

Crush 这一轮的变化集中在一件事上：内置 provider 多了一条**订阅账号登录**路径。`crush login` 新增 `grok`（别名 `xai`）平台，登录后凭 OAuth 令牌向 xAI 换取该订阅被授予的模型目录，目录落在新增的内部配置字段 `providers.xai.grok_models`。同时宿主修了一处由此暴露的判定缺陷：模型“存在/可用”与默认小模型的挑选此前只看 API-key 模型目录，订阅目录里的模型会被当成找不到。

这不影响 skills、hooks、MCP、原生插件与自定义 agent 五类机制的实现（对应的 `internal/skills/`、`internal/hooks/`、`internal/config/mcp.go`、`internal/agent/tools/mcp/` 与 agent 组装逻辑本轮都未出现在变化文件里），因此那五个主题的已发布章节保持原样。新写的只有 `custom_providers` 一章（v2），它同时把配置层面新增的字段与清理规则收了进去。

风险点有两个值得记住：一是 `oauth`、`chatgpt_models`、`grok_models` 三个字段带 `jsonschema:"-"`，不出现在 `crush schema` 的输出里，用户不能靠配置直接写；二是 xAI 的 API key 与 OAuth 令牌互斥，写入 API key 会顺手删掉登录留下的令牌与目录，退出登录则三种凭据一起清。这两条都是可观察行为，读者容易踩到。npm 上观察到 0.97.1，但本轮没有把它与任何章节或源码提交做版本映射。

## 变化的意义与证据边界

### 新增 xAI/Grok 订阅账号登录

影响 `providers.auth`、`providers.entry`、`providers.models`、`providers.metadata`、`providers.diagnostics` 五个问题，落在 `providers-entry`、`providers-auth`、`providers-protocol-models`、`providers-metadata`、`providers-diagnostics` 五个小节。

变化由 `internal/oauth/grok/`（新的 provider 授权实现）、`internal/login/login.go`（把 `grok` 注册为一等登录平台）、`internal/cmd/login.go` 与 `internal/cmd/logout.go`（命令入口）以及 `internal/config/{config,store,load}.go`（字段、拉取、互斥、启动刷新）共同产生。引用能证明到的边界：授权有两条路径——浏览器授权码加 loopback 回调（回调路径必须是 `/callback`，端口由操作系统分配，因为 xAI 按路径注册共享客户端的重定向 URI），以及 loopback 监听器起不来时的 RFC 8628 设备码回退；非交互环境打印 URL 并仍会尝试打开浏览器。仍缺的部分：xAI 侧的账号政策、令牌有效期与授权端点细节不由本仓库定义，固定来源里没有对应说明；设备流程的轮询节奏与失败提示也没有逐项定义。

### 订阅模型目录的判定与刷新

影响 `providers.models`、`providers.metadata` 与 `providers.diagnostics`。

`GetModel` 与 `IsModelAvailable` 现在跨 `models`、`chatgpt_models`、`grok_models` 三份目录查找，agent 构建选中模型时也改走 `GetModel`——这修掉了“只被订阅目录公布的模型被判为找不到”的情况。目录本身有三条刷新路径：登录后立即拉取、模型更新时惰性补齐（已有目录则跳过）、以及本轮启动刷新过 Catwalk 目录时顺带刷新；三者都是 best effort，失败只记 warning 并保留已有目录。引用能证明这些分支与注释语义；不能证明的是这些路径在真实网络下的成功率，本轮只做了源码阅读，没有运行 Crush。

### 其余主题的核查范围

`internal/agent/coordinator.go` 与 `internal/agent/prompt/prompt.go` 有改动：选中模型解析改走 `GetModel`、模型更新时多一次订阅目录懒刷新、提示词里的当前分支名改为直接读仓库而不再经 shell。但三个内置 agent 的入口、工具集、MCP 授权、上下文路径与委派机制都没变，已发布的自定义 agent 章节结论仍然成立，因此没有新建 edition。UI 动画、附件与编辑框、发布流水线，以及 Hyper 目录里 `deepseek-v4.1-flash` 的价格与默认输出上限变化，都不改变机制层结论。
