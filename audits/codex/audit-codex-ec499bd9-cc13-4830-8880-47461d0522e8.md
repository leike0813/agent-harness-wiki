## 给维护者的结论

本轮观察 `audit-codex-ec499bd9-cc13-4830-8880-47461d0522e8`：配置参考与 MCP 两个官方文档快照变化，Git `0c7efeb5..b0b0852e` 变化；npm 0.172.0 与 CLI/skills 文档未变。

按固定问题只维护了两道答案，两个主题各出一个新 edition：

- **configuration → `codex-cli-configuration-v7`（基于当前选中的 v5）**：managed permission-profile 的版本门槛（要求 Codex 0.138.0，0.137.0 及更早忽略 `allowed_permission_profiles` 与托管 `default_permissions`）已从文档删除，`config.migration` 的已发布答案因此变化，v7 删除该段并移除对应引用。`network_proxy` 描述删掉 `Codex 0.166.0` 版本门与"在策略验证器全部支持前保留别名"的建议，但保留 `[network_proxy]` 与别名 `[experimental_network]` 及"每层只用一名"规则，据此把同一小节的别名写法更正为 `network_proxy`（别名 `experimental_network`）。
- **mcp → `codex-cli-mcp-v4`**：MCP 文档新增按需启动机制。默认可选 stdio server 在已有可用工具清单（缓存目录）时可等到第一次工具调用才启动；`required = true` 的 stdio server 在 `startup_readiness = "catalog"` 时也可首次使用时启动；没有缓存工具清单则随 thread 启动；`features.mcp_lazy_stdio_startup = false`（文档默认 `true`）可让这些 server 随 thread 启动。`mcp.lifecycle` 的启动时机与 `mcp.capabilities` 的"缓存替代启动枚举、不替代活连接"边界随之更新。

其余变化结案为无答案变化，理由见下。本轮没有来源冲突、没有推翻已发布配置步骤、没有跨主题加载机制改变，因此未触发高影响独立复核。
