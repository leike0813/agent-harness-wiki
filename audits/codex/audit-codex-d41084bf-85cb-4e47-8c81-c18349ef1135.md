## 变化的意义与证据边界

### 托管策略顺序与配置文件层顺序是两回事

`codex-cli-configuration-v3` 的 `{#config-overrides}` 现在同时给出两条顺序：源码层优先级（随包默认 -10 到旧版托管 MDM 50）决定哪个 `config.toml` 覆盖另一个；新文档给出的托管策略顺序（仅当前操作系统的环境覆盖 → 全部操作系统的环境覆盖 → Global）决定哪份托管策略覆盖另一份，且高优先级策略即使不如低优先级具体也会胜出。影响 `config.overrides`，引用 `ref-codex-cli-config-managed-precedence-doc`。仍缺的是这套托管顺序在真实部署里的实际交付路径，来源只给了顺序本身。

### requirements.toml 钉住功能开关

`{#config-defaults-migration}` 记录 `[features]` 用与 `config.toml` 相同的规范键名固定运行时开关，未列出的键不受约束，并记录文档陈述的版本门槛：托管权限档位允许列表需要 Codex 0.138.0 或更新版本。影响 `config.defaults`（仍 partial）与 `config.migration`。版本号未绑定分发渠道，不能据此断定已安装版本行为。

### MCP 的 OAuth 注册与回调，以及 server 级 instructions 预算

`codex-cli-mcp-v3` 的 `{#mcp-auth}` 补上 `client_id` 优先于自动注册、回调 ID 由 MCP server URL（含路径与查询串）推导、授权服务器不声明 issuer 支持时回调后附加该 ID；`{#mcp-lifecycle-exposure}` 补上 `instructions` 只有前 512 个字符在 Codex 决定是否使用该 server 时可见，因此跨工具约束要写在这段前缀里。影响 `mcp.auth` 与 `mcp.capabilities`（仍 partial：resources 与 prompts 依旧无来源说明）。

### 已复核但未改写的范围

skills、hooks、custom_agents、native_plugins 四章的引用逐条在新提交上复核通过，本轮不新出版本。它们的章节内容不变是因为被引用的机制没有变，不是因为跳过了复查。
