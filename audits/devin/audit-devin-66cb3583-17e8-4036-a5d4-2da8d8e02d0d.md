## 给维护者的结论

本轮 31 个来源全部报 changed，读者可见的实质变化为零。30 个官方文档页面的字节变化几乎全部是文档站重新渲染：每页页尾新增一行 Mintlify 署名（“This documentation is built and hosted on [Mintlify](https://mintlify.com), a developer documentation platform.”）。唯一的内容改动是 `cli/extensibility/plugins/overview.md` 的 Metadata 小节把一句话收紧了措辞，语义不变。

因此七个主题的章节全部沿用 v1，本轮不改写任何正文。Devin CLI 闭源、没有可固定的源码 commit，全部结论仍为来源级知识（`version_applicability: unknown`），不绑定任何已发布版本。

`source-devin-npm` 报的 changed 不是版本变化：该来源在审计链里没有基线字段，扫描器按 `observed ≠ baseline` 判 changed；观察到的 `3000.6.11@sha512-q4oSmCGmnlOcUhJU9RyPRk7hAvR96A+uW0aggBQbRExGP4vcYeyM+V3Z6aEFWfG5PB/889V3+sRfPx3egQkYFw==` 与既有 `artifact-devin-npm` 记录的版本与 integrity 完全相同。本轮不据此新建任何版本映射。

## 变化的意义与证据边界

### plugins 元数据一句措辞收紧，不改变答案

上游把 “Only `name` is used for the plugin's **identity and namespace**; the rest are descriptive and shown by `devin plugins info`.” 改成 “Only `name` is used for the plugin's **namespace**; …”。`name` 依然是唯一决定命名空间、也唯一决定插件身份的字段，其余字段仍只作描述并由 `devin plugins info` 展示。`plugins.package` 的答案不受影响，`devin-cli-native_plugins-v1` 正文里“只有 `name` 参与身份与命名空间”这句仍然成立。

引用 `ref-devin-plug-metadata` 的摘录按原样保留：它锚定的是自己声明的旧快照，改摘录会让引用与所声明的原件不符。它是本轮 206 条引用里唯一没有在新原件中逐字命中的一条，命中的 205 条覆盖其余全部问题。

### 优先级页补齐的版本边界已有落点

`cli/reference/configuration/global-vs-local.md` 的 Configuration Layers 小节里，那条讲 MCP 专用文件的 Note 本轮补上了 “In CLI versions before v3000.3 (the Local 3.6 release)… newer versions migrate them to the dedicated files automatically on startup”。这是版本边界表述的补全，不是新机制：`mcp` 与 `configuration` 两章早已由 `ref-devin-mcpc-file` 与 `ref-devin-precedence-layers` 记录同一事实，并写明 v3000.3 前后 `mcpServers` 键的迁移行为，无需新增正文。

### 文档索引里有 8 个页面尚未登记

`docs.devin.ai/llms.txt` 列出 38 个 `/cli/` 页面，登记来源只有 30 个；反向核对，已登记的 30 个页面全部仍在索引内。未登记的是 `cli/acp/jetbrains`、`cli/acp/xcode`、`cli/acp/zed`、`cli/changelog/stable`、`cli/enterprise/windsurf-auth`、`cli/reference/keyboard-shortcuts`、`cli/reference/terminal-compatibility`、`cli/ssh`。

抽查两页确认影响有限：`cli/ssh` 只是 SSH 接入命令（`ssh devin-<id>@ssh.devin.ai`）与 `scp` 示例，无配置机制；`cli/enterprise/windsurf-auth` 提到 “CLI access” 的**按用户设置优先于团队默认策略**，而现有 `ref-devin-auth-access` 只覆盖 RBAC 自定义角色那一侧，这条优先级规则目前没有引用落点。登记新来源要写 `registry/sources/`，超出本轮 `knowledge/devin/` 与 `audits/devin/` 的写入范围，留给下一轮处理。

### 证据边界：本轮无法做新旧全文比对

30 个 artifact 记录声明的 `archive_path`（`archive/devin/artifact-<source-id>/raw.md`）在本工作树里全部不存在。核对后确认这是工作树级的现象而非本产品缺陷：全仓 685 个声明的 `archive_path` 有 640 个缺失，因为 `archive/` 被 `.gitignore` 排除，本监控工作树从未包含既往原件。因此本轮结论建立在“既有引用摘录是否仍逐字存在于新原件”之上，而不是新旧全文 diff。上游若在这轮只做了**新增**而未触及既有引用，摘录比对看不到；上面 8 个未登记页面的抽查是这一残余风险的一部分。
