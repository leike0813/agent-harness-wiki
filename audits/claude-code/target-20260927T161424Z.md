## 变化的意义与证据边界

### 官方文档有具体线索，精确版本关联缺失

归档的 Skills 页面谈到搜索位置和重名处理；MCP 页面谈到传输与本地、项目、用户范围；设置页面又提供 hooks、插件信任及配置层级的线索。这些材料可以指引下一步查哪里，却无法回答“`2.1.283` 的 Linux 原生 CLI 是否按这些规则加载”。例如 MCP 文档中提及 agent 文件和插件提供的 server，也不能据此推断两种机制在所选包中已经加载。

### 包已取得，不等于功能已运行

隔离包集使用 `--ignore-scripts`，所以主包的 `bin/claude.exe` 没被安装脚本替换；将它当成可用 CLI 会混淆分发状态与运行状态。要确认某个插件或 MCP server 的 `loaded`、`active`、`healthy`，还需要针对精确版本和受控配置的行为证据。在此之前，`partial` 不应被改写为 `unsupported`，也不应派生“原生插件已正常工作”的 Claim。
