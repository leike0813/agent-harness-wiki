## 两条命中项的证据与影响

### markdown custom agent 的五个路径键改以 agent 目录为基准（1.3.1，第 13 行）

`skills:`、`plugins:`、`rules:`、`agents:`、`hooks:` 里写成相对路径的条目，此前在 markdown custom agent 上——不论它作为子代理还是主代理运行——指向 agent 自身文件的相对条目都会被忽略；现在这类条目相对 agent 所在目录解析，因此 `agents: [child.md]` 可以调用同级 `child`。

这纠正了一个已发布说法。`custom_agents-v3` 依据 1.2.2 的条目写着「`agents` 的路径规则与 `skills` 相同，支持工作区相对、绝对与代理相对」，没有版本边界；而 1.3.1 说明代理相对这一条此前根本不生效。v4 在「入口、发现与 frontmatter 字段」一节明确区分：工作区相对在任何版本都按工作区定位，代理相对要到本次修复之后才按 agent 目录定位。

`skills` 章 v2 未对 agent frontmatter 路径基准作任何断言，因此无需改写。影响 `agents.entry` 与 `agents.format`（`agents.format` 仍为 partial——扩展字段依旧只有条目级证据）。

### `/plugin` 装卸插件的三条语义（1.3.1，第 12 行）

- Windows 上用 `/plugin` 安装、重装或卸载插件时，若该插件某个 MCP server 正在运行，CLI 先停止这些 server、再替换或删除插件目录、事后重启；被另一个 Antigravity 进程（另一个 `agy` 会话、Antigravity Hub、`remote-control` 守护进程）占用时，提示关闭后重试。
- 从 marketplace 安装不再覆盖来源不同的既有插件目录——这为 `plugins-install` 里既有的「重装精确替换受管目录」补上跨来源例外，两者并列成立。
- 插件清单、`mcp_config.json`、`hooks.json` 带 UTF-8 BOM 时也能加载。

影响 `plugins.install` 与 `plugins.lifecycle`。

## 为什么 mcp 章不改版

1.3.1 的 `/plugin` 条目讲的是插件目录被替换前后 CLI 对该插件 MCP server 的停启动作与跨进程占用提示，主体是 `/plugin` 安装流程，已记入 `native_plugins-v2` 并交叉链接；它没有改变 mcp 章登记的启动时机、超时、重连、禁用落盘路径或任何诊断入口。BOM 一条针对的是插件内的 `mcp_config.json`，而 mcp 章的 BOM 结论来自更早的独立条目 `ref-agy-mcp-changelog-bom`（Windows 上 UTF-8 BOM 的 MCP JSON 可解析），未被本次条目推翻。
