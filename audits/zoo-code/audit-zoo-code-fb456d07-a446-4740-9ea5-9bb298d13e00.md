## 决定性问题的回答

1. **provider 请求如何成形** —— 变。`openAiR1FormatEnabled` 此前只决定消息是否按 R1 格式转换，现在同一个判定还通过 `getModel()` 的 `preserveReasoning` 影响后续请求是否回传推理块（openai.ts 302-332 + Task.ts 6106-6115）。Anthropic 兼容路径的 adaptive thinking 请求新增 `display: "summarized"`（reasoning.ts 127-136）。逐 provider 覆盖关系不变：`OpenAiHandler` 的子类里 DeepSeek、Moonshot、Kimi Code、MiMo 都各自 `override getModel()`，因此不受这条合成影响。
2. **provider/model 元数据如何发现与缓存** —— 变。目录抓取与缓存分键从 `modelCache.ts` 里的 provider 名单改为 handler 契约：`ApiHandler.fetchModels?()` 负责抓取、`ApiHandler.getModelCacheScope()` 声明 `urlScoped`/`keyScoped`/`authScoped`，基类默认三项全 false（index.ts 121-131/170-185，base-provider.ts 154-160）。各 provider 的 scope 取值与旧名单逐项一致，所以键空间与持久化语义不变，变的是归属与新增的「无 `fetchModels` 即拒绝」错误路径（modelCache.ts 138-152/191-202）。
3. **用户配置什么** —— 变。用户可写档案字段集合未增删（`openAiR1FormatEnabled` 在基线 707f1442 已存在于同一 schema），但同一字段现在多一个作用：控制推理是否回灌上下文。
