## 结论与章节

- `custom_agents` → 新 edition `kimi-code-cli-custom_agents-v5`
  - `agents.invocation`：移除「分叉子 Agent」相关结论；`fork` 参数（含开关、schema 参数、兼容性检查、遥测字段）已删除，子 Agent 以默认 profile 起步、不继承父会话历史；`SelectTools` 不再受 `tool-select` 开关约束。
  - `agents.limits`：委派链终止只由父 Agent 绑定快照决定（不再出现「分叉不缩水」的表述）；工具可用性只由模型能力决定。
- `mcp` → 新 edition `kimi-code-cli-mcp-v4`
  - `mcp.definition`：`deferred` 不再是实验特性，只在模型声明 `dynamically_loaded_tools` 时改变披露方式。
  - `mcp.lifecycle`：MCP 服务实例按 program 共享并带引用计数（每个会话工作目录持 lease，最后一个 lease 释放才停 server）；会话/循环启动是唯一等待初始发现就绪的时点（受 per-server `startupTimeoutMs`/全局 `startup_timeout_ms` 约束）；基线固定后连上的 server 工具不进入该会话请求清单。
  - `mcp.capabilities` / `mcp.exposure`：重写按需加载机制（ToolSelect 解析器、初始提醒与 delta、`select_tools` 注入 system message、无动态加载能力时按普通声明发送）；删除「实验开关是前置条件」的旧步骤。
- `local_transcripts` → 新 edition `kimi-code-local_transcripts-v3`
  - `transcripts.schema`：固定 `TurnEndedPayload` 的必填/可选字段，并记录本版新增的 `replyModel`、`modelSteps[]`；保持 partial（`isKfc` 判定来源、`turn.prompt`/`turn.cancel` 字段仍未固定）。
  - `transcripts.cleanup` / `transcripts.diagnostics`：异主机名锁只在能取得 `.reclaim` 互斥文件时被回收；异主机 `.reclaim` 残留会让两次认领尝试后以 `session.occupied` 失败并需手工删除该文件。跨机器/容器共享数据目录时应只允许一个写者或关闭 `KIMI_CODE_SESSION_LOCK`。
